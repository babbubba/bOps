# V1.3 public track — entitlement boundary and plugin lifecycle UI

Status: **future; do not start before V1.2 and repository-topology gates close**
Recommended model effort: **molto alto**
Repository: `bOps`
Depends on: V1.2; private repository available; legally reviewed commercial-license draft

## Outcome

Add a product-neutral, fail-closed entitlement hook and safe local UI/API operations to upload,
enable and disable trusted plugins without placing commercial logic in the public repository.

## Entitlement ADR and implementation

- [ ] Define neutral request/decision contracts for subject/tenant, Skill/version, capability,
      target, tier/feature, validity and reason code.
- [ ] Place enforcement after approval validation and immediately before execution so stale or
      revoked entitlement cannot execute.
- [ ] Define offline/cache/clock-skew semantics; absence, invalidity and provider failure fail closed.
- [ ] Audit source category and decision without token/license contents.
- [ ] Keep read-only inspection available when execution entitlement is denied.
- [ ] Add architecture scans rejecting commercial names, prices, payment providers, private license
      identifiers, prompts, fixtures and playbooks in the OSS tree.

## Plugin lifecycle ADR and API

- [ ] Define administrator-only enable/disable/upload state transitions, idempotency, concurrency,
      recovery and audit.
- [ ] Define strict upload byte/file-count limits, accepted archive shape, traversal defense,
      quarantine/staging location and cleanup.
- [ ] Validate manifest schema, host/SDK compatibility, capabilities, dependencies, detached
      signature, publisher trust and risk ceiling before installation.
- [ ] Install atomically; a failed upload or activation never replaces the last known-good plugin.
- [ ] Reuse PluginManager/PluginHost; do not create a second loader or trust policy.
- [ ] Preserve the explicit warning that enabled in-process code has host privileges.

## Angular work

- [ ] Extend the V1.1-F catalog with role-gated enable/disable/upload controls.
- [ ] Show validation stages, publisher/signature/trust, compatibility and requested capabilities
      before final activation.
- [ ] Require explicit confirmation for activation and display rollback/recovery outcome.
- [ ] Prevent double submission and stale-state mutation with version/ETag handling.

## Validation

- [ ] Entitlement tests: valid, expired, future, revoked, wrong Skill/version/target, missing provider,
      cache/offline, clock rollback and post-approval revocation.
- [ ] Upload attack tests: zip slip, symlink, bomb, excess files/bytes, malformed manifest, unknown
      key, bad signature, incompatible SDK, dependency failure and crash mid-install.
- [ ] Authorization/CSRF/idempotency/concurrency tests for every lifecycle endpoint.
- [ ] UI tests for allowed/denied roles and recovery states.
- [ ] Release build, full suites, cross-platform CI and OSS leak scan.
- [ ] Coordinate public contract version with private provider consumption without copying private
      implementation into public tests.

## Definition of Done

- [ ] Entitlement is neutral, fail-closed and enforced at the execution point.
- [ ] Plugin lifecycle mutations preserve trust, last-known-good state and complete audit.
- [ ] No commercial implementation detail is present in `bOps`.
