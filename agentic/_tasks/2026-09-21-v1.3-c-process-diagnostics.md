# V1.3-C — advanced process diagnostics

Status: **future; starts only after V1.3-B**
Recommended model effort: **medio**
Repository: `bOps`
Depends on: V1.3-B complete

## Outcome
Complete process troubleshooting without adding `process.start`, shell access or environment dumping. Preserve existing process tools; extend `process.inspect` additively and add `process.metrics`, `process.tree`, `process.modules`.

## Public contract
### process.inspect
Keep existing parameter `pid` and existing JSON fields. Add nullable: `parentPid`, `executablePath`, `commandLine`, `user`, `privateMemoryMb`, `virtualMemoryMb`, `handleOrFdCount`, `cpuTotalMs`, `ioReadBytes`, `ioWriteBytes`. Permission-denied fields become null; one unreadable field must not fail the observation. Never return environment variables.

### process.metrics
Parameters: `pid` required; `sampleMilliseconds` optional default 500, range 200–5000.
Output: `pid,exists,sampleMilliseconds,cpuPercent,workingSetMb,privateMemoryMb,virtualMemoryMb,threadCount,handleOrFdCount,readBytesPerSec,writeBytesPerSec,pageFaultsPerSec,partial`.
CPU is host-normalized 0–100. If process exits between samples return `exists:false,partial:true`.

### process.tree
Parameters: optional `rootPid`; `maxDepth` default 4/max 16; `limit` default 200/max 2000.
Rows: `pid,parentPid,name,user,depth`, deterministic parent/PID order plus `complete,truncated,skipped`.

### process.modules
Parameters: `pid`; optional `limit` default 200/max 1000; `maxOutputBytes` default 32768/max 131072.
Rows: `name,path,baseAddress,sizeBytes,version`, unique by normalized path, with completeness metadata.

## Implementation
Use existing System.Core for manifests/DTOs/formatting/base classes and System.Windows/Linux only for native collection. No new public Abstractions members expected.

### Windows
- `System.Diagnostics.Process`: memory, threads, TotalProcessorTime, modules.
- Add `System.Management` only to System.Windows; query `Win32_Process` by PID for ParentProcessId, ExecutablePath, CommandLine and GetOwner.
- P/Invoke `GetProcessIoCounters` and `GetProcessHandleCount`.
- CPU rate = delta TotalProcessorTime / wall interval / Environment.ProcessorCount.
- No PowerShell, WMIC executable, SeDebugPrivilege, arbitrary Process.Start.

### Linux
- `/proc/<pid>/stat`: parent PID + CPU counters.
- `/proc/<pid>/status`: UID, memory, threads.
- `/proc/<pid>/cmdline`: NUL-separated command line.
- `/proc/<pid>/exe`: executable.
- `/proc/<pid>/io`: cumulative I/O.
- count `/proc/<pid>/fd`.
- resolve UID from local `/etc/passwd` only.
- `/proc/<pid>/maps`: coalesced modules.
Treat ENOENT as exit race and EACCES as partial visibility.

## Validation
- Extend System conformance for manifests and JSON shapes.
- Real Windows/Linux tests inspect the test process and a child process.
- Prove parent/child relation, non-negative metrics, bounds, cancellation, inaccessible/disappearing process behavior.
- Architecture tests continue to reject `process.start`, shell/system.exec and process environment dump.

## Definition of Done
The agent can identify process ancestry, ownership, launch command, executable, resource rates and modules with bounded typed evidence.
