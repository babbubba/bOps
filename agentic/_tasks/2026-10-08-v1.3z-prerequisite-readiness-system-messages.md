## Outcome

One product-neutral subsystem that tells bOps — and its administrator — whether each Tool and Skill Capability can run,
why not, and when that changed, for first-party packages and enabled plugins alike, without the Runtime naming any
package. Motivating future consumer: `system.dump_analyze` (required `kd.exe`, optional `dumpchk.exe`).

## Acceptance (whole task)

- Required prerequisite unavailable → registered, not available, never offered or executed.
- Optional prerequisite unavailable → available, degraded, one `Information` message.
- Repeated identical observations → no new message; recovery → `Information`; check failure → `Error`.
- One message per prerequisite transition, affected components bounded in metadata.
- Messages queryable by inclusive from/to, exact severity, case-insensitive text (AND), newest first, opaque keyset
  cursor, 50 default / 200 max; persisted across restart; 90-day retention.
- Frozen 1.0 SDK surface: zero missing lines; old constructors and `Requires` behaviour unchanged.
- Architecture suite green (core names no package, no generic execution tool).

**Exact decisions.**
- Required unsatisfied → registered, not available (hidden from catalog/`Resolve`/`ResolveForExecution`; Capability
  withheld from `GetAvailableSkills`/`Resolve`; a Skill with no available Capability is omitted). Optional unsatisfied →
  available + degraded. Prerequisite-level `Degraded` is satisfied. `SkillRegistry()` without probe fails closed only for
  Capabilities declaring `Requires`.
- Id in both lists, null list or blank optional id → registration refused. Legacy `Requires` entries are not newly validated.
- Prerequisite ids lowercase dotted; duplicate id across packages refused (first owner kept); provider registration atomic.
- Check timeout: descriptor value clamped 1–60 s (default 10 s) on the registry's `TimeProvider`; `WaitAsync` bounds
  token-ignoring checks. Throw → `Error/check-failed` (only `exceptionType` kept); timeout → `check-timeout`; Unknown
  or malformed outcome → `check-invalid-result`; caller cancellation propagates; unregistered id → unrecorded Unknown.
- Metadata: ≤ 32 entries, key `^[A-Za-z][A-Za-z0-9._-]{0,63}$`, strings ≤ 512, string arrays ≤ 32, ≤ 4,096 bytes; refuses
  secret-named keys (`*token` suffix, password, secret, apikey, credential, connectionstring, authorization, cookie, …),
  URL user-info and `Bearer ` values; re-validated on JSON read.
- Transitions per ADR-0049 §7 table; message `Source` `prerequisite/<id>`, `ComponentType` Prerequisite, metadata
  `prerequisiteId, state, previousState, checkCode, requirement (required|optional|unused), affectedComponentCount,
  affectedComponents (≤16)`, plus check detail as `detail.<key>` when it fits. Ids `Guid.CreateVersion7`.
- Query: inclusive from/to, exact severity, case-insensitive `instr` on invariant upper-case fold, AND; order
  `ticks DESC, id DESC`; cursor base64url `v1:<ticks>:<id>` (≤ 128 chars, invalid → `ArgumentException`); page 1–200
  (out of range → `ArgumentOutOfRangeException`, API should map to 400). Purge is strictly-older-than.

## Session 3 handoff — 2026-10-08

**Scope done.** Three backend correctness fixes, `agent.replan.threshold`, the System Messages page, documentation, the gate and the PR.
PR #91 untouched and not merged into this branch. `PR #91 can migrate windows.debugger.kd and dumpchk.exe onto this prerequisite
infrastructure after this PR is merged.`

**A — persistence failure is fail-closed.** `PrerequisiteReadinessService` no longer lets a check result that could not be durably
recorded reach the Tool/Skill snapshots. On a recorder failure it calls `PrerequisiteRegistry.AddHostObservation` with
`Error`/`state-record-failed` (fixed text, no exception text; the exception is logged), so required dependents are unavailable and optional
ones degraded; unrelated prerequisites are still recorded; the host overrides are replaced as a set at the end of every cycle
(`SetHostObservations`), and `GetLastResult` (hence `/api/prerequisites` and the boolean probe) gives them precedence. New `PrerequisiteCodes.StateRecordFailed`.

**B — declared-but-unregistered is observable.** After the checks, declared ids (Requires + OptionalRequires of every Tool and Skill
Capability, lower-cased, valid ids only) minus registered ids become host-observed `Error`/`not-registered` results recorded by the same
recorder: new message code `prerequisite.not-registered` (`Error` if a component requires it, else `Warning`), no invented remediation,
one message per prerequisite, deduplicated by fingerprint across refreshes and restarts, normal transition and recovery when a check is
registered later. `PrerequisiteRefreshReport.NotRegistered` counts them. `/api/prerequisites` shows `Error`/`not-registered` once observed.

**C — plugin lifecycle.** `PluginLifecycleEndpoints.EnableAsync/DisableAsync` run one `PrerequisiteReadinessService.RefreshAsync` after a
successful, non-replayed result and before the response. Failure (including cancellation) is caught, logged and never changes the committed
result. Nothing refreshes after a rejected/stale/unconfirmed/failed/replayed operation or after recovery. `bOps.PluginHost` still has no
reference to `bOps.Runtime`; plugin code never receives the service. The API test fixture can emit a plugin that contributes a check
(`PluginArchiveFixture(withCheck: true)`).

**Replan message.** `AgentRunner` gained a last optional `ISystemMessageStore? systemMessages` argument (all existing call sites compile
unchanged; the API's runner, `ExecutionRunnerFactory` and the CLI pass the store). `AgentRunnerOptions.ReplanWarningThreshold` (`int?`;
effective = configured, else `min(3, MaxLifetimeReplans)`; explicit value must be 1..MaxLifetimeReplans). Emitted by
`PublishReplanThresholdAsync` right after the accepted-replan commit when `LifetimeReplans == threshold`; the node is `NodeId.Local`
(the run does not carry another one; `TaskState` is built with it too). Best effort, 5 s bound, logged on failure.

**UI.** `/system-messages`; `SystemMessagesStore` (stale-response guard, cursor stack for exact Previous/Next, in-page de-duplication),
`SystemMessages` component, `localInputToUtcIso`, `enum.severity.*` and `systemMessages.*` EN/IT keys, nav entry. The optional compact
readiness summary was deliberately not added. e2e: `web/bops-ui/e2e/system-messages.e2e.ts` (E2E-13).
