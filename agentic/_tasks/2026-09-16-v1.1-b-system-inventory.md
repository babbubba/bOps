# V1.1-B — system applications, devices and hardware model

Status: **implementation complete; Windows/Linux CI validation pending**
Recommended model effort: **alto**
Repository: `bOps`
Depends on: V1.1-A complete

## Outcome

Provide bounded, deterministic and cross-platform read-only inventories through `system.apps`,
`system.devices` and an additive hardware-model field in `system.info`.

## Analysis and contract

- [x] Inventory current System Core/Windows/Linux manifests, DTOs, serializers and conformance tests.
- [x] Define common output schemas with explicit nullable/unknown fields; never substitute an empty
      value for “permission denied”, “source unavailable” or “not applicable”.
- [x] Define stable identity/deduplication rules, deterministic sort order, paging/limit behavior,
      truncation metadata and timeout/cancellation behavior.
- [x] Document supported Windows and Linux inventory sources and privilege requirements before code.
- [x] Preserve the existing `system.info` contract additively; older consumers must deserialize it.
- [x] Write an ADR only if a new dependency or public abstraction boundary triggers workflow rules.

## Test-first implementation

- [x] Add cross-platform conformance tests for the shared output shapes.
- [x] Implement Windows application inventory without shell composition; cover machine/user and
      32/64-bit sources deliberately and deduplicate deterministically.
- [x] Implement Linux application inventory for the explicitly supported package databases; report
      unsupported managers rather than guessing or returning false completeness.
- [x] Implement Windows and Linux device inventory from bounded native/system sources; normalize
      category, vendor, model/name, device identity and status where available.
- [x] Add hardware model to both platform `system.info` implementations with explicit fallback.
- [x] Apply configured maximum items/output bytes before data reaches audit or the model.
- [x] Keep all three tools Risk `Read`; add no driver-update or arbitrary probe operation.

## Validation

- [x] Real Windows tests cover installed app variants, duplicate entries, devices and unavailable
      fields without relying on one developer machine's exact inventory.
- [ ] Real Linux tests cover each supported package family in CI/container targets and absence of a
      package database.
- [x] Contract tests prove deterministic ordering, limits, truncation markers and cancellation.
- [x] Architecture tests prove no OS-specific type leaks through abstractions/core.
- [ ] Release build, non-live suite and Windows/Linux CI are green.
- [x] README tool table and operator documentation state coverage and limitations precisely.

## Definition of Done

- [x] The three outputs are useful, bounded and schema-compatible across Windows/Linux.
- [x] Unsupported or inaccessible data is distinguishable from an empty machine.
- [x] No generic execution capability or unbounded inventory output was introduced.
