## Interpretations made while writing the contracts

ADR-0030 fixes the design, not every signature. These were decided here; none changes behaviour the ADR
states, but V1.2-C onward should read them before relying on the ADR text alone.

1. **The correlation block is on the `AuditEvent` base type, not on four named events.** ADR section 8
   names four events, section 1 says every audit event of a delegated run carries both operator and
   agent, and `ModelCallAuditEvent` is not among the four although Discovery and Diagnostic call a model.
   The base type satisfies the stronger sentence and means a new event type cannot forget it.
2. **The full envelope is stored in each role record, not only its hash.** A resumed role must run under
   exactly the authority it was granted, and a hash cannot be turned back into one. The runtime may narrow
   the stored envelope from the current role profile on resume, never widen it. The hash is still what is
   audited, computed by `DelegationHasher.ComputeEnvelopeHash`.
3. **`AllowedTools` is any tool the agent may invoke, not only Read evidence tools.** ADR section 3 says
   "allowed tool names for Read evidence". Remediation calls side-effecting tools from an approved plan,
   so a single set covers both; which calls consult it is the runtime's rule (V1.2-C).
4. **Approval is history, not authority.** `DelegationRun.Approval` records who approved which hash. It
   exists for the UI and audit; a resume must still obtain a fresh human approval (ADR-0022).
5. **`ParentAgentId` is `null` when the parent is the orchestrator**, which is runtime code with no agent
   identity. Depth lives only on the envelope (one source of truth).
6. **Role profiles and the operator's request are not in the SDK.** They are host configuration and a
   runtime input; V1.2-C decides where they live. `bOps.Runtime` must not reference `bOps.Policy`, so C
   needs an interface the host implements over the policy configuration.
7. **`Evidence.Provenance` has an `internal` setter**, following `CapabilityManifest.Package` (rule A11):
   only `bOps.Runtime`, an `InternalsVisibleTo` friend, can stamp it, so a Capability cannot claim its
   evidence came from another agent. It is still serialized. V1.2-F must add `InternalsVisibleTo` for
   `bOps.Memory` (or an equivalent) for the source-generated store serializer; the tests already prove the
   source generator handles this shape from a friend assembly.

## Open question for V1.2-C

ADR-0030 says an empty intersection in *any* dimension is a denial. Read literally, a Discovery role that
legitimately has no Capabilities, or a Verification role that has no Skills, would be denied. The contract
represents an empty set as "nothing permitted" and never as "unrestricted", so it supports either reading.
C must state, per role kind, which dimensions are required (and so deny when empty) and which may be empty,
and record that as an ADR-0030 clarification before enforcing it.

## Finding: `ToolParameterType` was renumbered in V1.1

The V1.1-H API diff compared member names and reported "zero removed or changed members" against the 1.0
close-out (`891dae2`). A reflection dump that also records enum values shows that V1.1-A inserted
`ToolParameterType.PathList` between `Path` and `Duration` (commit `0381b70`), moving `Duration` from 5 to 6
and `Enum` from 6 to 7. The C# compiler inlines enum values into every assembly built against the SDK, so a
package built against 1.0 that declares a `Duration` or `Enum` parameter would be read as `PathList` or
`Duration` by a 1.1 host.

Impact: none observed. Every use in this repository is symbolic and rebuilt together, no runtime store
persists the enum, and no stable 1.0 SDK was ever published (the previews are workflow artifacts only). It
is still a break of the additive-only promise, and it is cheapest to fix while nothing external exists.

Fix, in its own commit: `PathList` is now the last member with the explicit value 7, restoring the 1.0
values of `Duration` (5) and `Enum` (6). This is source-compatible; a binary built against the 1.1 previews
must be recompiled (there are no such external binaries). `FrozenContractValuesTests` now pins every member
of all ten 1.0 enums to its 1.0 value, and fails when `PathList` is put back in the middle. The binding
listing in `agentic/01-architecture-rules.md` was updated to match.
