# V1.3-E — storage topology, latency and health

Status: **future; starts only after V1.3-D**
Recommended model effort: **medio**
Repository: `bOps`
Depends on: V1.3-D complete

## Outcome
Create a dedicated read-only Storage family so bOps can distinguish application/database slowness from storage slowness/failure. Existing `system.disk` and `system.io` stay compatible quick summaries.

## Package layout
Create `bOps.Packages.Storage.Core`, `.Windows`, `.Linux` plus conformance/platform tests.

## Tools
### storage.disks
Rows: `id,name,model,serial,busType,mediaType,sizeBytes,logicalSectorBytes,physicalSectorBytes,rotational,removable,readOnly`.

### storage.partitions
Optional diskId and limit. Rows: `diskId,partitionId,name,startBytes,sizeBytes,type,boot,readOnly`.

### storage.mounts
Rows: `source,mountPoint,fileSystemType,totalBytes,freeBytes,usedPercent,readOnly,mountOptions,inodeTotal,inodeFree,inodeUsedPercent`.

### storage.io
Optional device and `sampleMilliseconds` default 1000/range 500–5000.
Rows: `readsPerSec,writesPerSec,readBytesPerSec,writeBytesPerSec,readLatencyMs,writeLatencyMs,queueDepth,utilizationPercent`.
Unavailable latency/queue values are null, never fabricated from throughput.

### storage.health
Optional device. Rows: `device,health,operationalStatus,temperatureC,powerOnHours,mediaErrors,reallocatedSectors,wearPercent,smartAvailable,source,detail`.
Health enum: healthy/warning/critical/unknown. Unknown is not healthy.

## Windows
- Add `System.Management` to Storage.Windows.
- WMI/CIM: Win32_DiskDrive, Win32_DiskPartition, Win32_LogicalDisk + associations.
- Prefer `MSFT_PhysicalDisk` in `root\Microsoft\Windows\Storage` for health where available.
- PhysicalDisk performance counters for ops/sec, bytes/sec, Avg Disk sec/Read/Write, queue, % Disk Time.
- Ambiguous perf instance→disk mapping must stay unresolved rather than guessed.

## Linux
- `/sys/block` and `/sys/class/block` for devices/partitions.
- `/proc/self/mountinfo` + P/Invoke `statvfs` for filesystem bytes/inodes.
- sample `/proc/diskstats` twice for IOPS, throughput, latency, queue/inflight and utilization.
- base health from sysfs.
- if `smartctl` exists, direct fixed `smartctl -j -a -- <validated-device>`; no shell. Device must be an enumerated /dev block device. Missing smartctl => partial health.

## Bounds
All Read. Default list 200/max 2000; output default 64 KiB/max 256 KiB; sample max 5 s. Never expose raw SMART/WMI dumps.

## Validation
Real Windows/Linux sources, sampling non-negative invariants, cancellation, unavailable health sources, ambiguous mapping, representative SMART JSON fixture and environment-gated real smartctl smoke.

## Definition of Done
bOps can correlate disks, partitions, mounts, capacity/inodes, IOPS, latency, queue/utilization and hardware health.
