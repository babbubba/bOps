## Objective

A fresh installation defaults to a deterministic, tool-capable model configuration; OpenRouter router
mode stays **supported** but is no longer the **recommended default**; optionally, an explicitly
configured, ordered fallback list recovers from transient/capacity failures without embedding vendor
semantics in `bOps.Runtime`.

## Confirmed defects addressed

**C-20**: `src/core/bOps.Api/appsettings.json` ships `"Model": "openrouter/free"`. In task 88f97dda,
12 successful calls were served by 7 different actual models (`ling-3.0-flash-sante`,
`nex-n2.5-pro`, `ling-3.0-flash-fin`, `lfm-2.5-2.6b`, `nex-n2.5-mini`, `dots-3-note-preview`, …), the
free tier returned `429 free-models-per-min` seven times before the failing upstream was chosen, and one
router-selected upstream enforced a stricter tool contract (C-01).

## Source finding IDs

F-17.

## Scope

1. Default configuration: a fixed, tool-capable model for the default provider (choose with the
   operator; document the choice); `openrouter/free` documented as exploration-only, non-deterministic.
2. Settings UI: when a router model is configured, show a clear notice ("the actual model may change on
   every call; not recommended for troubleshooting sessions"); the step model-info already shows
   `requested → actual`.
3. Documentation: supported vs recommended provider/model configurations; rate-limit implications of
   free tiers.
4. **Optional** (only if the operator approves the ADR): host-level ordered fallback list
   (`ModelProvider:Fallbacks: [{Provider, Model}]`) implemented as a composite `IChatModel` in
   `bOps.Hosting`/`bOps.Api`, switching only on HARDEN-2 kinds `Transient`, `RateLimited`, `Timeout`,
   `Unreachable` after same-provider retries are exhausted; never on `Authentication`, `InvalidRequest`,
   `MalformedResponse`; each attempt audited with the actual provider and model (additive
   `ActualProvider` if needed).
5. E2E-4 fallback variant.

## Out of scope

- Removing router support.
- Any provider-name or router logic in `bOps.Runtime`.
- Cost accounting beyond what providers report.

## Architecture constraints

The Runtime sees one `IChatModel`; composition happens in the host. All calls audited. No fallback on
permanent errors.

## Likely components/files

`src/core/bOps.Api/appsettings.json`, `ProviderResolution.cs`, `Program.cs`, `bOps.Hosting` (composite,
if implemented), `src/core/bOps.Api/SettingsEndpoints.cs`, `web/bops-ui/src/app/features/settings/*`,
i18n, `docs/` operations pages, `bOps.Api.Tests`.

## ADR prerequisite

A new ADR **only if the fallback composite is implemented**. Default/docs/UI notice changes need none.

## Public contract impact

Configuration default change (documented); additive fallback configuration and optional additive
`ActualProvider` on model-call records if the composite is built.

## Security implications

Fallback must not route to a provider the administrator did not configure; secrets per provider stay in
the existing secret/vault mechanism.

## Dependency gates

HARDEN-2 complete (failure kinds). Canonical order: after HARDEN-12.
