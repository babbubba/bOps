## Objective

`storage.health` returns a real, honest health status on every supported Windows host, distinguishing
healthy, warning, unhealthy, unknown, unsupported and partial evidence.

## Confirmed defects addressed

**C-17**: `WindowsStorageCollector.Health()` queries
`SELECT DeviceId,FriendlyName,HealthStatus,OperationalStatus,MediaType,Temperature,Usage,Size FROM MSFT_PhysicalDisk`.
`MSFT_PhysicalDisk` has no `Temperature` property, so the query fails deterministically ("the specified
property does not exist", surfaced as `InvalidQuery`) and every disk is reported `unknown` with
`Storage health provider unavailable: InvalidQuery.`. Proven on the operator workstation: without
`Temperature` the query returns 1 row with `HealthStatus=0`. `MSFT_StorageReliabilityCounter` returned
access denied to a non-elevated identity.

## Source finding IDs

F-09.

## Scope

1. Remove `Temperature` from the `MSFT_PhysicalDisk` projection; keep only properties that exist.
2. Map `HealthStatus` per the class documentation: `0` healthy, `1` warning, `2` unhealthy, `5` unknown,
   anything else unknown with detail.
3. Optional reliability counters via `MSFT_StorageReliabilityCounter` (associated to each physical disk):
   temperature, maximum temperature, wear, read/write errors, power-on hours. Access denied → keep the
   disk's health, set evidence `partial` with detail "reliability counters require elevation".
4. Distinguish states in the output: `healthy`, `warning`, `unhealthy`, `unknown`, `unsupported` (the
   Storage WMI namespace absent), and a per-device `partial` flag/reason.
5. Fallback to `Win32_DiskDrive` only for identity when the Storage namespace is unavailable; never
   report `Win32_DiskDrive.Status` as SMART health.
6. Correct `source` labelling (`MSFT_PhysicalDisk`, `MSFT_StorageReliabilityCounter`,
   `Win32_DiskDrive`).
