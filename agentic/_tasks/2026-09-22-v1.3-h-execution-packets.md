## Contract clarification fixed before implementation

`identity.users.enabled` is `bool?`.

- Windows may return true/false from an authoritative local-account source.
- Linux must not infer disabled state from shell/profile.
- Linux sources allowed by the task (`/etc/passwd`, `/etc/group`, local APIs) may return
  `enabled:null` when disable/lock state is not knowable without forbidden credential metadata.
- With `includeDisabled=false`, remove only users positively known disabled. Users with
  `enabled:null` stay in the result.

Unknown is better than false certainty.

## H2 — Windows identity + sessions

**Model:** Luna Medium.

### Native recipe
- current: `WindowsIdentity.GetCurrent`, `WindowsPrincipal`;
- users: NetAPI32 `NetUserEnum`;
- groups: `NetLocalGroupEnum`, `NetLocalGroupGetMembers`;
- sessions: WTS APIs.

Do not query Active Directory and do not silently convert a local query into a domain crawl.

### Semantics
`elevated` is based on the effective local Windows token/principal evidence chosen by the
implementation; document exact evidence.
`serviceAccount` is positive only from well-defined account/session evidence; unknown remains false
only if the contract is truly binary and source is complete—otherwise introduce/retain completeness
at result level rather than guessing.

### Tests
Real current identity and session enumeration on windows-latest; deterministic interop parsing/unit
coverage where a specific account state cannot safely be created.

## H3 — Linux identity + sessions

**Model:** Luna Medium.

### Sources
- current ids: `getuid/geteuid`;
- users: `/etc/passwd`;
- groups: `/etc/group`;
- never read `/etc/shadow`;
- sessions: fixed `loginctl list-sessions` / `show-session` when available, bounded local fallback
  only.

### Rules
- shells such as `nologin` or `false` do **not** imply `enabled:false`;
- network directory users absent from local files imply incomplete source, not empty certainty;
- fallback session source must be documented and bounded;
- direct process calls use fixed executable/ArgumentList and no shell.

### Tests
Real local passwd/group parsing on Linux; fixtures for malformed/edge lines; session path real smoke
where available and explicit incomplete result where not.

## H4 — system.time + system.reboot_pending

**Model:** Luna Medium.

### Read first
Existing System.Core/Windows/Linux tool shells and V1.3-A event source patterns.

### system.time
Shared output:
`utcNow,localNow,timeZoneId,utcOffsetMinutes,dst,clockSource,ntpConfigured,ntpSynchronized,timeServiceStatus,source,complete`.

Windows:
- BCL time/timezone;
- Windows Time service status;
- documented W32Time registry values;
- no parsing localized `w32tm` output.

Linux:
- fixed `timedatectl show` explicit properties;
- if unavailable, BCL + bounded service/config evidence;
- fallback must set completeness honestly.

Do not duplicate exact offset measurement: `network.ntp_probe` owns it.

### system.reboot_pending
Windows sources independently probed:
- CBS RebootPending;
- Windows Update RebootRequired;
- PendingFileRenameOperations;
- pending rename/domain state where readable.

Return reason identifiers, not large raw registry values.

Linux:
- `/var/run/reboot-required`;
- only explicitly enumerated distro markers;
- unsupported distro/source -> `complete:false`, never `pending:false, complete:true` by assumption.

### Tests
Timezone-safe; fixture detectors for each reboot reason; real smoke; permission/unsupported cases.
