## Interpretations made in M

None changes an ADR.

1. **The release tag matches the SDK version.** The version is `1.2.0-preview.8` in `bOps.Abstractions.csproj`; the release workflow reads it
   from there, so the tag is `v1.2.0-preview.8` and nothing was bumped, so no lock file changed. The earlier previews, `preview.1` to
   `preview.7`, were development increments of the contract and were never tagged.
2. **The crash scenario ends the run by settling, not by reconciliation.** The interesting branch (a step that turns out to have run) is
   proved end to end with real tools. The branch where verification cannot confirm the step (`RequiresReconciliation` and an operator's
   decision) is proved at the runtime and API levels with scripted tools (`DelegationRunnerDurabilityTests`, `DelegationsEndpointsTests`);
   it is not repeated here with real tools.
3. **A resumed run has two Verification roles.** One confirms the step the crash left unsettled, using the read-back the tool declares; the
   run's final Verification role is the last one. Both have their own agent ids. This is the existing behavior, now visible in a gate test.
4. **The Angular UI is covered by its unit tests and the production build, not by a browser run against a live API in this gate**, as in V1.1-H.
5. **No install, enable, disable and remove smoke test of a signed plugin was run.** V1.2 changes nothing in the plugin path, and the V1.1-H one
   stands; the plugin tests in `bOps.PluginHost.Tests` pass.
6. **The one-off tool that took the 1.0 baseline is the test itself.** `WriteSnapshot_WhenAsked` writes the description of another build when
   two environment variables are set and does nothing otherwise; the baseline is never remade from a later build.
