# V1.4 public track — Managed Agent and secure Coordinator protocol

Status: **future; do not start before V1.3 closes**
Recommended model effort: **molto alto**
Repository: `bOps`
Depends on: V1.3 entitlement; remote threat model; certificate/secret operations ready

## Outcome

Publish the Managed Agent host/profile, minimal interoperable protocol and outbound node connector
needed by the private Community Coordinator while keeping execution, policy, approval, entitlement,
verification and primary audit local. Preserve the existing standalone OSS runtime as an independent
mode rather than converting it into a managed-only Agent.

## ADR and protocol design

- [ ] Supersede local-only ADR-0011 only for this gated transport; retain local execution authority.
- [ ] Formalize the strict boundary: the Coordinator reasons/orchestrates but never invokes an
      operational package directly; every action, including on its host, goes through an enrolled
      Agent using the same authorization/execution path.
- [ ] Define a Managed Agent profile with no required LLM, provider API key, commercial Skill
      knowledge or direct Internet dependency; retain SQLite task state and authoritative local audit.
- [ ] Define node identity, explicit enrollment, mTLS or equivalent mutual authentication,
      credential rotation/revocation and compromise recovery.
- [ ] Define a separately versioned protocol with negotiation, compatibility window, downgrade
      resistance and canonical signed envelopes.
- [ ] Permit only typed objectives/plans/capability requests; no raw command, shell or arbitrary SQL
      field exists anywhere in the schema.
- [ ] Define nonce/freshness/replay rules, idempotency keys, ordering, retry and reconciliation.
- [ ] Define `AccountId`, `CoordinatorInstallationId`, `NodeId`, `AgentInstanceId`, server-assigned
      immutable `NodeKind` and authenticated Local Agent enrollment without trusting client claims.
- [ ] Define a Coordinator-signed delegated Node Lease that is node/Coordinator/freshness/scope
      bound and cannot amplify the vendor-signed entitlement.
- [ ] Define tenant/subject/role/target binding without embedding private tenancy implementation in
      the OSS contract.
- [ ] Keep commercial knowledge, playbooks and prompts Coordinator-side. Protocol payloads contain
      only typed objectives/plans/capability requests and structured evidence/results that cannot
      mutate local policy or runtime state.

## Test-first public implementation

- [ ] Implement an outbound connector; no mandatory inbound administrative execution listener.
- [ ] Implement the native self-contained Managed Agent host as Windows Service and systemd service
      with bounded local state, enrollment, health and logs; no direct vendor/LLM/update Internet path.
- [ ] Validate envelope signature, freshness, protocol, target, entitlement and local policy before
      accepting work.
- [ ] Translate accepted objectives into the existing local orchestration path; no remote shortcut.
- [ ] Write audit locally first, then ship immutable events with retry/idempotency/reconciliation.
- [ ] Buffer under explicit disk/count/time budgets and fail visibly when retention is exhausted.
- [ ] Add connection health/registration status without exposing credentials.
- [ ] Accept update payloads only through the Coordinator channel after local signature/hash,
      compatibility and rollback validation; never download directly from GitHub/GHCR/vendor services.

## Validation

- [ ] Contract tests shared with `bOps.Commercial` through versioned published artifacts, not source
      duplication.
- [ ] Test mTLS identity, tenant/target mismatch, replay, downgrade, revocation, expired work,
      altered approval hash and local policy stricter than remote policy.
- [ ] Test offline operation, reconnect, duplicate delivery, out-of-order audit and reconciliation.
- [ ] Test with Agent Internet egress blocked while enrollment, task/evidence flow, approval,
      remediation, verification, audit sync and Coordinator-delivered update remain functional.
- [ ] Test Community accounting contracts: three Remote nodes accepted, fourth denied, one
      Coordinator-assigned Local Agent accepted in addition, second/pseudo-local denied, remote
      revocation immediately frees a slot, controlled re-enrollment does not double-count and
      cross-account/Coordinator enrollment fails.
- [ ] Add public architecture tests proving the Managed Agent contains no commercial Skill/provider
      knowledge; require the private companion task to prove the Coordinator cannot acquire a
      direct operational executor dependency.
- [ ] Test protocol compatibility across every supported node/Control Plane version pair.
- [ ] Threat-model review and penetration tests for the new network boundary.
- [ ] Release build, full suites and Windows/Linux CI.

## Definition of Done

- [ ] A registered node receives a typed objective and executes only after all local gates.
- [ ] Invalid/replayed/downgraded/unauthorized instructions fail closed.
- [ ] Audit synchronization is tenant-bound, ordered/reconciled and never the primary local record.
- [ ] Public code contains only essential interoperable contracts and connector behavior.
