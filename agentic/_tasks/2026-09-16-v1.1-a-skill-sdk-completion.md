# V1.1-A — complete the Skill/Capability SDK

Status: **next implementation task**
Recommended model effort: **molto alto**
Repository: `bOps`
Depends on: ADR-0023, ADR-0024 and the current green V1.1 baseline

## Outcome

Deliver the missing executable Skill boundary and prove it with one non-commercial OSS sample Skill
that uses the existing governed tool pipeline from evidence gathering through verified reporting.

## Scope guardrails

- No V1.2 agent identity, delegation or orchestration.
- No database/product name in core contracts and no commercial playbook.
- Skill logic is deterministic package code, not an extra model call.
- `IToolInvoker` exposes only Risk `Read` tools from the requesting package and still applies
  validation, policy, timeout, audit and output limits.
- ExecutionPlan steps continue through the ordinary policy/approval/verification path; there is no
  privileged Skill executor.

## Sample Skill

- [ ] Choose a harmless, product-neutral scenario using existing read tools and at most one safe,
      verifiable typed action.
- [ ] Gather evidence through restricted `IToolInvoker`; never manufacture evidence in the sample.
- [ ] Produce findings referencing evidence IDs and an immutable ExecutionPlan.
- [ ] Exercise policy, approval hash, execution, independent verification and a structured report.
- [ ] Package/load the sample through the real plugin boundary rather than test-only DI shortcuts.

## Validation

## Definition of Done

- [ ] The new ADR is accepted and implementation matches it.
- [ ] Public contracts are documented, serializable and SemVer-compatible.
- [ ] Restricted invocation cannot cross package/risk boundaries.
- [ ] Contextual policy and audit are enforced end to end.
- [ ] Persistence behavior is truthful and tested.
- [ ] The real sample satisfies the V1.1 Skill Definition of Done.
