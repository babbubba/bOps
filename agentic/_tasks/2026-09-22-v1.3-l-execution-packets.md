## L1 — DB port 5432/1433 unreachable

**Model:** Luna Medium.

Evidence sequence:
`network.dns_query -> network.routes -> network.sockets -> firewall.status/rules -> service.status/config -> system.events -> network.port_check`.

Required deterministic cases:
1. name resolution failure;
2. route absent/unusable evidence;
3. no local listener;
4. listener bound only to unexpected/local address;
5. service stopped/failed;
6. local firewall block evidence;
7. port reachable.

Assertions:
- never infer remote firewall state;
- absence of local firewall evidence is not proof that network path is open;
- no-listener and service-down diagnoses are distinct;
- DB-specific waits/locks are explicitly deferred to commercial DB Skills.

## L2 — service keeps crashing

**Model:** Luna Medium.

Sequence:
`service.status/config/dependencies -> system.events -> system.crashes -> process.tree/metrics -> storage.io -> system.memory/swap`.

Cases:
- service failed + matching event/crash;
- process exits before metrics sample;
- crash backend unavailable;
- storage pressure coincident but not proven causal.

Assertions:
- evidence correlation is described as correlation unless source proves cause;
- incomplete crash/event sources must remain visible in verdict reasoning.

## L3 — DB/application became slow

**Model:** Luna Medium.

Sequence:
`system.cpu -> system.memory -> system.swap -> process.metrics -> storage.io -> storage.health -> system.events -> network.interface_stats`.

Cases:
- CPU saturation;
- memory/swap pressure;
- storage latency/queue pressure;
- network error/drop evidence;
- no host bottleneck found.

Last case must end with an explicit handoff: DB Skill adds native waits/locks/query stats; host
evidence alone must not invent a DB root cause.

## L4 — file cannot be replaced/deleted

**Model:** Luna Medium.

Sequence:
`fs.stat -> fs.permissions -> fs.locks -> process.inspect/tree/modules`.

Cases:
- permission evidence;
- real lock holder;
- incomplete lock visibility;
- target disappeared/raced.

Do not recommend or invoke process termination automatically. The scenario proves diagnosis only.

## L5 — TLS connection fails

**Model:** Luna Medium.

Sequence:
`network.dns_query -> network.routes -> network.port_check -> network.tls_probe -> certificate.inspect -> system.time -> network.ntp_probe`.

Cases:
- TCP refused;
- handshake failure;
- trust failure;
- hostname mismatch;
- expired/not-yet-valid certificate;
- local clock/time synchronization concern.

Assertions:
- trust failure is not reported as TCP failure;
- time evidence may explain validity symptoms but must not be promoted to root cause without matching
  certificate/time evidence.

## L6 — scheduled job did not run

**Model:** Luna Medium.

Sequence:
`scheduler.inspect/history -> identity.current/users/groups/sessions -> service.status/config -> system.events -> fs.permissions` where relevant.

Cases:
- scheduler disabled;
- scheduler history failure;
- target service disabled/stopped;
- user/identity evidence incomplete;
- file permission evidence;
- history backend unavailable.

Never execute the scheduled target command as a test or remediation.

## L7 — reboot/update regression

**Model:** Luna Medium.

Sequence:
`system.reboot_pending -> system.update_history -> system.updates -> system.events -> system.drivers`.

Cases:
- pending reboot after known update;
- recent failed update;
- driver/module change evidence;
- update/history source incomplete.

Do not claim temporal correlation proves the update caused the regression.

## L8 — Docker-hosted service failure

**Model:** Luna Medium.

Sequence:
`docker.containers -> docker.inspect/logs -> docker.images -> network.sockets -> storage.io -> system.events`.

Cases:
- container stopped;
- image/inspect evidence;
- application not listening;
- storage pressure;
- daemon unavailable.

No Docker exec/create/compose/prune is introduced.
