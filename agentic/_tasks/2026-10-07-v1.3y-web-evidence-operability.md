## Trigger and observed evidence

Real local task `c27e248e-6507-4397-8f62-db428e490168` ended as `MaxStepsReached`
on 2026-10-07 after 15 steps and no final answer. The two `web.fetch` failures were not
transport failures and were not caused by a missing search container:

- step 12 called `web.fetch` with `data:text/plain,placeholder`; the tool correctly rejected a
  non-HTTP(S) URI;
- step 14 embedded an `EvidenceRead/v1` directive in a fabricated
  `https://example.invalid/...` URL; DNS resolution correctly failed;
- the task exhausted `Agent:MaxSteps` after those calls; `web.fetch` itself did not terminate the
  task;
- `Web:Search:BaseUrl` was empty. Consequently `web.search`, which requires the
  `web.searxng` capability, was intentionally absent from the model-visible tool catalog;
- `web.fetch` has no SearXNG or Docker dependency. It directly fetches one public HTTP(S) URL
  under the existing SSRF and resource policy;
- the repository documents SearXNG in `docs/security/web-network-policy.md`, but the README Quick
  start does not provide an operational local-development path and the repository currently ships
  no SearXNG Compose resource or AppHost resource.

This packet is a post-close operational follow-up. It does not reopen V1.1-E or the completed
HARDEN-1 through HARDEN-14 train.

## Outcome

Make the distinction and readiness of `web.search`, `web.fetch`, and the internal bounded-history
`EvidenceRead/v1` protocol obvious to operators and robust for local models. A fresh local operator
must be able to tell whether search is unavailable, start or point to a trusted JSON-enabled
SearXNG instance when desired, verify it, and avoid mistaking `web.fetch` for either search or an
internal evidence reader.

## Implementation result — 2026-10-07

The operator authorized the composition-first implementation. `bOps.AppHost` now provisions a
pinned SearXNG container by default, injects its Aspire endpoint into `bops-api`, waits for
`/healthz`, and can omit the optional resource with `Searxng__Enabled=false`. The repository-owned
settings enable JSON explicitly, disable the public-instance limiter for this loopback-only
development instance, and receive a generated startup secret rather than a committed credential.

The incident classification found no provider/runtime conversion of `EvidenceRead/v1` into a tool:
the OpenAI-compatible fallback already preserves the directive as assistant text and the runtime's
exact recognizer already handles it internally. The local model had proposed an ordinary
`web.fetch` call itself. The runtime prompt and both web-tool descriptions now say explicitly that
the directive is neither a URL nor a tool call; a core regression locks that guidance. No typed
tool, protocol change, ADR amendment or relaxation of the web policy was necessary.

Real validation used Docker 29.7.2 and the AppHost composition: `/healthz` returned `200 OK`,
`/search?q=bOps&format=json` returned 20 results, the opt-in `SearxngClientLiveTests` contract passed,
and authenticated `GET /api/tools` exposed both `web.search` and `web.fetch`. A Qwen smoke reached
the configured llama.cpp endpoint and ended immediately in the existing bounded authentication
diagnostic (`401 Invalid API Key`, one synthetic failure step); no usable local-model credential was
available in the test process, so this run did not exercise Qwen reasoning after the prompt change.
The Release solution build completed with zero warnings and the full non-live-model solution test
gate passed; the focused AppHost, Web and Runtime projects passed 2, 62 and 1,542 tests respectively.

## Non-goals

- No public SearXNG instance selected automatically.
- No mandatory Docker dependency for bOps or `web.fetch`.
- No relaxation of SSRF/private-network controls.
- No support for `data:` or `file:` in `web.fetch`.
- No public or production SearXNG deployment; this implementation is confined to the development
  AppHost and remains removable with one configuration switch.

## Definition of Done

- A fresh operator can follow Getting Started to understand the two web tools, optionally bring up
  and verify search, configure the correct endpoint and see why search is unavailable when it is
  not configured.
- `web.fetch` is demonstrated independent of SearXNG and continues to reject non-HTTP(S) and
  forbidden destinations.
- Internal bounded evidence is retrieved through a deterministic, security-preserving path that a
  supported local model does not confuse with outbound web access.
- The real failure mode from task `c27e248e` is covered by regression evidence and no longer ends
  silently as generic step-budget exhaustion.
