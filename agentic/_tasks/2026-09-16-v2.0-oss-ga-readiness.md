# V2.0 public track — enterprise GA readiness

Status: **future; do not start before V1.9 closes**
Recommended model effort: **molto alto**
Repository: `bOps`, coordinated from the private root
Depends on: all prior milestones and completed legal/commercial review

## Outcome

Prove that the public runtime, SDK, packages, local UI and node connector are supportable as the OSS
foundation of the V2.0 hybrid product.

## Security and reliability

- [ ] Update the threat model for every boundary added since V1.0 and close findings from an
      independent review/penetration test.
- [ ] Define measurable SLOs and resource/performance budgets for runtime, API, plugin loading,
      large inventories, audit and node transport.
- [ ] Run endurance, soak, concurrency, chaos and recovery tests on representative Windows/Linux
      nodes.
- [ ] Perform backup/restore and disaster-recovery drills for every public durable store, including
      encrypted vault, manifests, tasks and audit.
- [ ] Test key/certificate rotation, entitlement revocation propagation and offline behavior.

## Compatibility and operations

- [ ] Publish supported OS, .NET, plugin SDK, protocol and upgrade compatibility matrices.
- [ ] Test supported forward/backward data migrations and rollback/canary procedures.
- [ ] Produce privacy-aware telemetry guidance, retention controls and redacted support bundles.
- [ ] Verify local-only operation remains supported without the commercial Control Plane.
- [ ] Validate installation, upgrade and uninstall paths in clean supported environments.

## Supply chain and documentation

- [ ] Produce signed, reproducible artifacts with SBOM, checksums and provenance on all supported
      platforms.
- [ ] Run dependency/license/vulnerability review and update notices without importing private
      licensing into OSS artifacts.
- [ ] Complete operator, security, recovery, upgrade, SDK/plugin and troubleshooting documentation.
- [ ] Align README, CHANGELOG, HANDOFF and release notes with exact tested support claims.
- [ ] Obtain explicit authorization before tags, publication or release creation.

## Definition of Done

- [ ] Security review findings are resolved or explicitly accepted by the operator with rationale.
- [ ] Recovery, migration, compatibility and SLO evidence is reproducible.
- [ ] Public artifacts contain only Apache-compatible scope and complete notices/provenance.
- [ ] The release is supportable without overstating untested environments or autonomy.
