## Objective

No model failure is unaudited, no task stays `Running` after its executor stops, and every provider
failure is classified, bounded in retry, and shown to the operator with an actionable, sanitized
reason.

## Confirmed defects addressed

- **C-03** a provider timeout (default `HttpClient` 100 s → `TaskCanceledException`) escapes
  `SendAsync`, `CallModelAsync`, `ContinueAsync` and `AgentTaskLauncher`: no audit event, no
  `ModelCallRecord`, no terminal status, task left `Running` (the likely cause of the 30-minute
  unaudited gap in task 88f97dda — hypothesis H-1).
- **C-15** retry delays 100/200 ms, `Retry-After` ignored, only 408/429/502/503/504 transient,
  401/500/"context length" unclassified; the provider's reason (e.g. the Poolside function-name
  message, `provider_name`, `previous_errors`) is only in `ResponseJson`, which the API view strips,
  so the UI shows "Provider 'OpenRouter' returned HTTP 400 (BadRequest) for the chat completion
  request." with nothing actionable.
- Launcher backstop gap: an unexpected exception from the detached run leaves the persisted status
  unchanged.

## Source finding IDs

F-02 (BLOCKER), F-12. Hypothesis H-1.

## Scope

1. **Timeout containment.** In `CallModelAsync`, catch `OperationCanceledException` when
   `!ct.IsCancellationRequested` (mirror `ExecuteWithTimeoutAsync`), record a `ModelCallRecord` and a
   `ModelCallAuditEvent` with outcome `Failure`, kind `Timeout`, and end the task through the normal
   failure path. A genuine task cancellation still propagates.
2. **Launcher backstop.** `AgentTaskLauncher.TryRunDetached`: any exception other than an operator
   cancellation loads the latest state and persists `Failed` with a terminal reason
   ("unexpected runtime failure: …", bounded), logs it, and never leaves `Running`.
3. **Failure classification** (additive): `Transient`, `RateLimited`, `Timeout`, `Unreachable`,
   `Authentication`, `InvalidRequest`, `ContextOverflow`, `MalformedResponse`, `Unknown`. Carried on
   `ModelProtocolException`, `ModelCallRecord` and `ModelCallAuditEvent`. Classification lives in the
   provider packages (status code + body inspection); the runtime only reads the kind.
4. **Bounded retry**: same-provider retry for `Transient`, `RateLimited`, `Timeout`, `Unreachable`
   only; exponential backoff with jitter; honour `Retry-After` (seconds or HTTP date) up to a cap;
   per-call time budget and maximum attempts configurable; never retry `Authentication`,
   `InvalidRequest`, `MalformedResponse`. Each attempt is visible in the audit (either one audit event
   per attempt or one event carrying an attempt count and last kind — decide in the ADR-0013
   amendment).
5. **Explicit HttpClient timeout**, configurable per provider, larger than one attempt and smaller
   than the per-call budget.
6. **Sanitized provider reason**: extract `error.message`, a nested `metadata.raw` JSON `message`,
   `provider_name`, and a summary of `previous_errors` codes; strip `user_id` and any identifier or
   key-shaped value; bound to about 500 characters; put it in `ErrorMessage` (task step, audit, API
   view). `ResponseJson` stays in the stored record and stays stripped from the default view.
7. **Terminal reason on the task** for a model failure: kind + sanitized reason, so the UI can say
   "provider authentication failed — check the key in Settings" or "provider rejected the request:
   <reason>".

## Out of scope

- Resume semantics, attempts and budgets (HARDEN-3).
- UI rendering of the new reasons beyond what the existing step view already shows (HARDEN-4).
- Cross-provider fallback (HARDEN-13).
- Context-overflow compaction retry (HARDEN-8 uses the `ContextOverflow` kind produced here).

## Architecture constraints

- `bOps.Runtime` stays vendor-agnostic: it never parses provider bodies; it reads the kind.
- Every call is audited whatever the outcome (rule S9 / principle 4); the audit hash chain format stays
  compatible (additive property).
- No unbounded retries; no retry of a permanent error.

## ADR prerequisite

**ADR-0013 amendment** (model-call audit outcome): failure kinds, timeout auditing, per-attempt retry
auditing, sanitization rule. Accepted before implementation.

## Public contract impact

Additive: `ModelProtocolException.FailureKind`, `ModelCallRecord.FailureKind`,
`ModelCallAuditEvent.FailureKind` (+ attempt information per the ADR). Configuration: additive
provider timeout/retry keys.

## Security implications

- Sanitization must never let API keys, bearer tokens, user identifiers or prompt content into the
  audit log or the UI; unit-test the sanitizer against realistic bodies including the incident body.
- Retry must not amplify cost unboundedly: per-call budget and maximum attempts are mandatory.

## Dependency gates

HARDEN-1 complete. HARDEN-3 and HARDEN-13 depend on this packet.

## Acceptance criteria

- [ ] A fake provider stalling longer than the timeout yields an audited model-call failure with kind
      `Timeout`, a `Failed` task with a terminal reason, and no task left `Running`.
- [ ] An exception thrown inside the detached run persists `Failed`.
- [ ] 429 with `Retry-After: 2` is retried after ≥ 2 s within budget; 503 retried with backoff; 401 and
      400 are not retried.
- [ ] A 401 produces kind `Authentication` and a reason naming provider configuration.
- [ ] The incident 400 body produces a reason containing the Poolside function-name message and
      `provider_name`, without `user_id`.
- [ ] Every attempt is visible in audit as defined by the ADR-0013 amendment.
- [ ] E2E-4 and E2E-5 pass with deterministic fakes.

## Required tests

- Fake handler sequences: stall, 429 + `Retry-After`, 503 ×2 then 200, 400 with body, 401, 500,
  malformed JSON body, "context length exceeded" body.
- Sanitizer unit tests with the incident body and bodies containing key-shaped strings.
- Launcher test: runner throws a non-cancellation exception → `Failed` persisted.
- Cancellation test: operator cancel still ends `Cancelled`, not `Failed`.

## Required platform evidence

Deterministic tests on Windows and Linux CI. Optional opt-in live smoke of a 401 (invalid key) per
provider, non-gating.
