# Post-V2.0 — bilingual public README

Status: **future; start only after V2.0 documentation stabilizes**
Recommended model effort: **medio**
Repository: `bOps`
Depends on: V2.0 release and stable English operator messaging

## Outcome

Provide equivalent English and Italian public entry points without allowing roadmap, security or
licensing claims to drift.

## Design

- [ ] Keep English canonical for code, API, normative `agentic/` documents and technical terms.
- [ ] Choose one discoverable structure: concise root language selector with `README.en.md` and
      `README.it.md`, or an equivalent structure approved at task start.
- [ ] Define stable section IDs/keys so CI can compare structure and required warnings.
- [ ] Keep generated/current status facts in one source or verify them automatically; do not maintain
      two independent manual status tables.

## Implementation and review

- [ ] Translate meaning, not identifiers, commands, tool names, legal identifiers or paths.
- [ ] Preserve security cautions, open-core boundary, trademark status and Apache-2.0 meaning.
- [ ] Validate every relative link and code block from both documents.
- [ ] Add CI checks for section parity, required notices and broken links.
- [ ] Obtain native-language review for clarity and legal/security-sensitive wording.

## Definition of Done

- [ ] Both entry points are easy to discover and equivalent in product/security meaning.
- [ ] Status and roadmap facts cannot silently diverge.
- [ ] All links/checks pass and English remains the normative technical source.
