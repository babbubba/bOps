# V1.2-F — durable state, step journal and reconciliation

Status: **planned**
Recommended model effort: **alto**
Repository: `bOps`
Depends on: V1.2-E complete
Governing ADR: `docs/architecture/adr/0030-privilege-reducing-multi-agent-delegation.md`

## Outcome

Persist delegation runs and resume without repeating side effects (ADR-0030 section 7). The ADR fixes the state machine, so this is implementation, not design; if a state cannot be expressed, stop and amend by a new ADR.

## Checklist

- [ ] Failing tests first, including a crash test at every durable state transition (between intent and execution, between execution and outcome, between roles, during approval, during verification).
- [ ] `SqliteDelegationStore` in `bOps.Memory`: transactional replace of the whole aggregate; restrictive file permissions on both platforms; `TaskState` and `ITaskStore` unchanged.
- [ ] Journal intent before and outcome after, only for side-effecting steps; read-only roles restart from their beginning against remaining budget; bounded resume count.
- [ ] Approvals are never persisted: resume requires a fresh human approval of the same plan hash. D returns a `DelegationRun` from memory (`Journal` empty, nothing stored) and asks the human through `IPlanApprovalProvider`; a resumed run asks again through the same provider.
- [ ] An ambiguous step is reconciled by its declared `VerificationSpec`; `Refuted` or `Inconclusive` ends as `RequiresReconciliation`; no automatic retry.
- [ ] Operator reconcile (accept as done, or abandon) is administrator-only and audited.
- [ ] Start is idempotent on a caller-supplied key.

## Definition of Done

- [ ] No completed side effect is repeated after any injected crash.
- [ ] Every ambiguous state fails closed and is visible.
