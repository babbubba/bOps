# V1.2-F — durable state, step journal and reconciliation

Status: **in progress** (F1 store done 2026-09-19; journal, resume, reconcile and idempotent start in the runner remain)
Recommended model effort: **alto**
Repository: `bOps`
Depends on: V1.2-E complete
Governing ADR: `docs/architecture/adr/0030-privilege-reducing-multi-agent-delegation.md`

## Outcome

Persist delegation runs and resume without repeating side effects (ADR-0030 section 7). The ADR fixes the state machine, so this is implementation, not design; if a state cannot be expressed, stop and amend by a new ADR.

## Checklist

- [ ] Failing tests first, including a crash test at every durable state transition (between intent and execution, between execution and outcome, between roles, during approval, during verification).
- [x] (F1) `SqliteDelegationStore` in `bOps.Memory`: transactional replace of the whole aggregate; restrictive file permissions on both platforms; `TaskState` and `ITaskStore` unchanged.
- [ ] Journal intent before and outcome after, only for side-effecting steps; read-only roles restart from their beginning against remaining budget; bounded resume count.
- [ ] Approvals are never persisted: resume requires a fresh human approval of the same plan hash. D returns a `DelegationRun` from memory (`Journal` empty, nothing stored) and asks the human through `IPlanApprovalProvider`; a resumed run asks again through the same provider.
- [ ] An ambiguous step is reconciled by its declared `VerificationSpec`; `Refuted` or `Inconclusive` ends as `RequiresReconciliation`; no automatic retry.
- [ ] Operator reconcile (accept as done, or abandon) is administrator-only and audited.
- [ ] Start is idempotent on a caller-supplied key.

## Definition of Done

- [ ] No completed side effect is repeated after any injected crash.
- [ ] Every ambiguous state fails closed and is visible.

## Progress

**F1, the store (2026-09-19).** `SqliteDelegationStore` implements `IDelegationStore` over one table (`delegations`: id, status,
actor, idempotency key, updated time, the run as JSON). A start takes the write lock (`BEGIN IMMEDIATE`), so twelve concurrent
starts with one key create exactly one run; the key is unique per actor. A save is one `UPDATE` and fails for a run that was
never started. Every connection waits for a writer and syncs each commit to disk; the file is owner-only on Linux. 14 tests
against a real file; five deliberate defects (a deferred transaction, the key not scoped to the actor, a save of an unknown run
accepted, the wrong recency order) are caught. The full-sync pragma is a durability setting a test cannot observe, so it is
not covered by one. Not yet wired into a host, and nothing calls it from `DelegationRunner`.

Remaining: F2 journal intent and outcome around each side-effecting step, with the run saved at each transition; F3 resume
(fresh human approval of the same hash, restart of read-only roles against the remaining budget, bounded resume count); F4
reconciliation by `VerificationSpec` and `RequiresReconciliation`; F5 administrator-only accept or abandon; F6 idempotent start
through the store; crash tests at every transition.
