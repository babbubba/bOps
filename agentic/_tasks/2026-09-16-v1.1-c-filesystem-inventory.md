# V1.1-C — bounded filesystem size and immutable inventory

Status: **in progress**
Recommended model effort: **alto**
Repository: `bOps`
Depends on: V1.1-B complete; filesystem path policy and S11

## Outcome

Add `fs.size` and a reusable bounded inventory service that can safely summarize large trees and
produce the immutable manifest foundation required by V1.1-D.

## Required design

- [x] Inspect current Filesystem tools, path-policy resolution, symlink handling, result DTOs and
      platform tests.
- [x] Write an ADR if the inventory/manifest becomes public contract or durable runtime state.
- [x] Define normalized inputs: one path, maximum depth, maximum entries, top-N count and whether an
      exact durable inventory is requested. Every limit has a host-enforced ceiling.
- [x] Define deterministic traversal/sort rules and entry identity metadata sufficient for stale
      detection without hashing every file's contents.
- [x] Define lifecycle, storage, expiry and cleanup for manifests; IDs are unpredictable and scoped
      to node/actor/task as required by the ADR.
- [x] Define an honest partial/truncated result: limit exhaustion is never represented as a complete
      size calculation or an approval-ready exact manifest.

## Test-first implementation

- [ ] Add tests for file, empty directory, nested tree, inaccessible entry, symlink/reparse point,
      path escape, cancellation, concurrent mutation, depth/entry/time ceiling and integer overflow.
- [ ] Add `fs.size` as Risk `Read` using the existing Filesystem package boundary.
- [ ] Stream enumeration and aggregation; do not retain every entry when only a summary is requested.
- [ ] Return file count, directory count, total bytes, top-N entries, completion/truncation state,
      elapsed metadata and bounded warnings.
- [ ] Do not follow symlinks/reparse points unless a future separately approved contract permits it.
- [ ] When exact inventory is requested, write entries incrementally to bounded durable storage,
      canonicalize/order them, compute the manifest hash and return only summary/reference/hash.
- [ ] Ensure manifest content never enters normal telemetry, model context or a single audit event.

## Scale and validation

- [ ] Add scale tests at 10,000 files proving bounded memory, bounded response size and cancellation.
- [ ] Add real Windows/Linux path, permissions and symlink tests.
- [ ] Add deterministic manifest/hash tests across repeated enumeration of an unchanged tree.
- [ ] Prove any incomplete enumeration cannot be marked approval-ready.
- [ ] Run Release build, non-live suite and Windows/Linux CI.
- [ ] Document configuration knobs, ceilings, manifest retention and cleanup.

## Definition of Done

- [ ] `fs.size` remains responsive and honest for large trees.
- [ ] Exact inventories are complete, immutable, addressable and hash-verifiable without flooding
      browser, LLM, audit or memory.
- [ ] All path checks and symlink behavior comply with S11.
