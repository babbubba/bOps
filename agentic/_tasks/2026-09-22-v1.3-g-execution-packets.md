## Contract clarifications fixed before implementation

### service.config

Keep the parent fields and add `enablementState`:

`exists,name,displayName,description,executable,arguments,workingDirectory,user,startupType,enabled,enablementState,restartPolicy,dependencies,dependents,source,complete`.

`enabled` is nullable. Do not force systemd states into a false boolean.

Systemd normalization:

| UnitFileState | enabled | enablementState | startupType |
|---|---:|---|---|
| enabled, enabled-runtime | true | native value | automatic |
| linked, linked-runtime, alias | null | native value | unknown |
| disabled | false | disabled | disabled |
| static | null | static | static |
| indirect | null | indirect | unknown |
| generated, transient | null | native value | unknown |
| masked, masked-runtime | false | native value | disabled |
| other/empty | null | native-or-unknown | unknown |

The mapping is diagnostic, not a claim that systemd exactly matches Windows SCM semantics.
Preserve the native state in `enablementState`.

Windows `enablementState` uses normalized values `enabled`, `disabled`, or `unknown`.

### scheduler stable ids

- Windows Task Scheduler: canonical task path.
- systemd timer: unit name, for example `backup.timer`.
- cron: `cron:<sha256-prefix>`, deterministic over normalized source identity + normalized entry
  identity. The canonical input includes source class, owner/user when known, canonical source path
  where applicable, and normalized schedule+command text. The id is an observation key only.
- Never use a cron id as a mutation token. Cron remains read-only.

## G1 — shared Service contract

**Model:** Luna Low, escalate to Luna Medium only for compile/test issues.

`service.dependencies` accepts optional `direction` (`both|requires|dependents`, default `both`)
and integer `limit` (1–1000, default 100). Out-of-range limits are rejected, never clamped.
Its bounded result exposes `relations`, `count`, `truncated`, `complete`, and `source`, with
deterministic ordering. `count` is the number of returned relations, not an inferred total. If
more relations are observed than `limit`, return at most `limit`, set `truncated=true` and
`complete=false`. If the visible set fits, `truncated=false` and `complete` reflects source
completeness. Preserve safely available evidence under permission/source restrictions with
`complete=false`. Empty results have `count=0`, `truncated=false`, and `complete=true` only when
the relevant source was observed completely.

## G2 — Windows service configuration and enablement

**Model:** Luna Medium. Escalate a concrete P/Invoke blocker to Terra Medium while available.

### Read first
- G1 files;
- existing `WindowsServiceStatusTool.cs`, `WindowsServiceStartTool.cs`,
  `WindowsServiceToolProvider.cs`;
- Windows service tests and existing Windows test fixture service.

### Native recipe
Use SCM APIs directly; no `sc.exe`, WMI or PowerShell:
- `OpenSCManager`;
- `OpenService`;
- `QueryServiceConfig`;
- `QueryServiceConfig2` for description, delayed-auto-start and failure actions;
- `ChangeServiceConfig` for enable/disable.

Use SafeHandle or equivalent deterministic handle cleanup. Do not request more SCM/service access
rights than the operation needs.

### Mapping
- binary path -> executable + arguments with a deterministic Windows command-line parser;
- service account -> `user`;
- AUTO_START + delayed flag -> automatic-delayed;
- AUTO_START -> automatic;
- DEMAND_START -> manual;
- DISABLED -> disabled;
- dependencies/dependents normalized and sorted deterministically.

Do not claim a working directory unless Windows provides authoritative evidence; return null.

### Mutation
- enable changes disabled -> demand/manual unless the existing non-disabled startup type can be
  preserved from preflight. Do not invent automatic startup as the default.
- disable changes startup type to disabled.
- neither starts/stops the service.

### Required tests
Real test-owned service:
- automatic/manual/disabled mapping where fixture control permits;
- delayed-auto mapping if CI fixture can own it, otherwise parser/native fixture + explicit skip;
- dependency shape;
- enable then config confirms `enabled:true`;
- disable then config confirms `enabled:false`;
- nonexistent service;
- access denied/incomplete evidence;
- no implicit state transition running/stopped.

## G3 — Linux service configuration and enablement

**Model:** Luna Medium.

### Read first
- existing Linux Service tools/provider;
- the fixed `systemctl` invocation pattern already used in the package;
- G1 shared contract.

### Native recipe
Direct process invocation only, `UseShellExecute=false`, `ArgumentList`; executable is fixed
`systemctl`.
Allowed invocations:
- `systemctl show -- <unit>` with explicit `--property=` list;
- `systemctl enable -- <unit>`;
- `systemctl disable -- <unit>`.

No arbitrary switches from model input; validate unit names before invocation.

### Properties
At minimum parse:
`Id,Description,FragmentPath,ExecStart,User,Group,WorkingDirectory,UnitFileState,Restart,Requires,Wants,After,Before`.

Do not parse localized human prose.

### Required tests
Real Linux unit where CI supports systemd, plus deterministic property fixtures:
- all UnitFileState mappings in the table above;
- static is `enabled:null`, not false;
- masked is disabled but preserved as masked;
- ExecStart normalization;
- Requires/Wants/dependents bounds;
- enable/disable verification;
- command invocation contains no shell and no caller-controlled option injection.

## G5 — Windows Task Scheduler

**Model:** Luna Medium; Terra Medium only for an isolated COM interop blocker.

### Native recipe
Task Scheduler 2.0 COM API. Do not use `schtasks.exe` or PowerShell.

Recursively enumerate folders with explicit folder/task ceilings. Stable id is canonical task path.
Never return passwords or credentials from task definitions. Do not dump raw XML.

History:
- use Microsoft-Windows-TaskScheduler/Operational;
- filter by task path/name;
- bounded window/rows;
- if log unavailable/disabled -> evidence with `complete:false`.

Mutations:
- enable/disable only a task identified by a list/inspect stable id;
- verify via `scheduler.inspect`.

### Tests
Real test-owned scheduled task:
list -> inspect -> disable -> verify -> enable -> verify.
History test accepts unavailable operational log only with `complete:false`, never fake empty-complete.

## G6 — Linux systemd timers and cron inventory

**Model:** Luna Medium.

### systemd
Direct fixed `systemctl list-timers` / `systemctl show` calls with ArgumentList.
Prefer stable machine-readable/property output; do not parse locale-dependent table prose when a
property form exists.

Enable/disable only systemd timers and verify via inspect.

### cron sources
Read only:
- `/etc/crontab`;
- `/etc/cron.d`;
- `/etc/cron.hourly`, daily, weekly, monthly;
- readable user spool locations explicitly discovered by bounded known-path probes.

Do not filesystem-scan for cron files.

Per-entry output must distinguish:
- source type;
- owner when known;
- schedule;
- target/command text;
- parse warning;
- complete/incomplete source status.

If a source path is not readable, inventory remains available with `complete:false`.

History:
journald where available with fixed query arguments; otherwise `complete:false`.

Cron enable/disable requests must fail explicitly as unsupported in this batch.
