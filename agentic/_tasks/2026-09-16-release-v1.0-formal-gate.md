# Formal V1.0 release gate

Status: **done for `v1.1.0-preview.2`; a stable V1.0 tag was never created (see Evidence)**
Recommended model effort: **medio**
Repository: `bOps`
Depends on: completed V1.0 implementation and explicit authorization to create/push a tag

## Outcome

Prove the existing V1.0 implementation through the real release workflow and retain inspectable
evidence for every published artifact. This task does not change V1.0 product scope.

## Preconditions and stop conditions

- [x] Confirm the exact release commit with the operator; do not infer it from a branch name.
- [x] Confirm the intended tag, initially expected to be an RC such as `v1.0.0-rc.1`.
- [x] Obtain explicit authorization immediately before creating or pushing the tag.
- [x] Verify the selected commit is reachable from protected `main`, CI is green, and the tree is
      clean except for separately identified documentation work.
- [x] Stop if the tag already exists with a different target, if signing identity is unavailable,
      or if any workflow permission/secrets prerequisite is unknown.

## Execution checklist

- [x] Synchronize the AppHost dependency lock with the centrally configured SourceLink dependency
      and verify a complete solution restore with `--locked-mode`.
- [x] Tag `v1.1.0-preview.1` (commit `b80a113`) failed run 35380761600: Linux `NU1004` on the
      host-specific AppHost lock; Windows SBOM step lacked `npm ci`. Tag is left in place; fixes on
      branch `fix/release-pipeline-prereqs`, released under `v1.1.0-preview.2` (SDK version bumped).
- [x] Review `.github/workflows/release.yml`, version inputs, RIDs and artifact naming without
      changing behavior merely to make a run pass.
- [x] Run Release build, non-live tests, Angular production build/tests and SDK pack locally.
- [x] Create and push only the approved tag (`v1.1.0-preview.2`).
- [x] Observe the authoritative Windows/Linux workflow to terminal state.
- [x] Download the workflow manifest and verify checksums, SBOM presence, provenance/attestation,
      NuGet metadata, versions and expected files for every RID.
- [x] Smoke-test one Windows and one Linux artifact in clean environments when available.
- [x] Record failures honestly; fix on a new commit/tag rather than moving an existing tag.

## Required evidence

- [x] Release URL/run ID and immutable tag-to-commit mapping.
- [x] Artifact inventory with checksum verification result.
- [x] SBOM and attestation verification result.
- [x] Test/build logs or durable workflow links.
- [ ] README/CHANGELOG/HANDOFF updated from “implementation complete” to the exact released state.

## Definition of Done

- [x] The approved tag identifies the intended immutable commit.
- [x] All release jobs are green on Windows and Linux.
- [x] Reproducible artifacts, packages, SBOMs, checksums and attestations are present and verified.
- [x] No credential, local path or private artifact was published.
- [ ] Documentation names the released version and any remaining production limitations exactly.
