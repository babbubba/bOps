# Formal V1.0 release gate

Status: **ready, operator-gated**
Recommended model effort: **medio**
Repository: `bOps`
Depends on: completed V1.0 implementation and explicit authorization to create/push a tag

## Outcome

Prove the existing V1.0 implementation through the real release workflow and retain inspectable
evidence for every published artifact. This task does not change V1.0 product scope.

## Preconditions and stop conditions

- [ ] Confirm the exact release commit with the operator; do not infer it from a branch name.
- [ ] Confirm the intended tag, initially expected to be an RC such as `v1.0.0-rc.1`.
- [ ] Obtain explicit authorization immediately before creating or pushing the tag.
- [ ] Verify the selected commit is reachable from protected `main`, CI is green, and the tree is
      clean except for separately identified documentation work.
- [ ] Stop if the tag already exists with a different target, if signing identity is unavailable,
      or if any workflow permission/secrets prerequisite is unknown.

## Execution checklist

- [ ] Review `.github/workflows/release.yml`, version inputs, RIDs and artifact naming without
      changing behavior merely to make a run pass.
- [ ] Run Release build, non-live tests, Angular production build/tests and SDK pack locally.
- [ ] Create and push only the approved tag.
- [ ] Observe the authoritative Windows/Linux workflow to terminal state.
- [ ] Download the workflow manifest and verify checksums, SBOM presence, provenance/attestation,
      NuGet metadata, versions and expected files for every RID.
- [ ] Smoke-test one Windows and one Linux artifact in clean environments when available.
- [ ] Record failures honestly; fix on a new commit/tag rather than moving an existing tag.

## Required evidence

- [ ] Release URL/run ID and immutable tag-to-commit mapping.
- [ ] Artifact inventory with checksum verification result.
- [ ] SBOM and attestation verification result.
- [ ] Test/build logs or durable workflow links.
- [ ] README/CHANGELOG/HANDOFF updated from “implementation complete” to the exact released state.

## Definition of Done

- [ ] The approved tag identifies the intended immutable commit.
- [ ] All release jobs are green on Windows and Linux.
- [ ] Reproducible artifacts, packages, SBOMs, checksums and attestations are present and verified.
- [ ] No credential, local path or private artifact was published.
- [ ] Documentation names the released version and any remaining production limitations exactly.
