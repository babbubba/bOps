## Objective

Add a read-only Windows tool that analyzes one kernel crash dump with Microsoft's `kd.exe` and returns bounded, structured
evidence suitable for an LLM. The evidence covers the bugcheck, the debugger's attribution, the failure bucket, the stack,
modules, symbol state and the kernel black boxes. It closes the gap where `system.stability` and `system.crashes` can name
a dump file but cannot look inside it.

Motivating case: `C:\WINDOWS\Minidump\100626-20984-01.dmp`, bugcheck `0x1E`, about 2026-10-06 14:03 UTC, about 11 MB.

## Operator decisions already fixed

- Backend: the Debugging Tools for Windows command line. `kd.exe` is required and `dumpchk.exe` is optional. No DbgEng
  COM, WinDbg automation, PowerShell or `cmd.exe`.
- Kernel dumps only. No user-mode dumps, CDB or `process.dump_analyze`.
- One `path` argument. There is no debugger command, symbol path, script or timeout parameter.
- Approved roots are `%SystemRoot%\Minidump\**`, `%SystemRoot%\LiveKernelReports\**` and exactly
  `%SystemRoot%\MEMORY.DMP`. Configurable roots are deferred.
- Capability `windows.debugger.kd`. The tool is hidden when `kd.exe` is absent, and nothing is ever auto-installed.
- **Text first, XML later** (decided 2026-10-08): no Debugging Tools were installed on the development workstation and the
  shape of `!analyze -xml` output is undocumented. V1 parses only marker-delimited text. Fixtures are synthetic and
  labelled as such.
- The global `Agent:DefaultToolTimeout` stays unchanged. The conflict is recorded in ADR-0048 §10.

## Gates

- [x] The ADR and the D-entry are written before the implementation is merged.
- [x] The path policy and the invocation containment are tested before the parser:
  - the policy rejects relative, UNC, device, ADS, out-of-root and `..` paths, and paths with quotes or shell or debugger
    syntax;
  - a real junction escape is rejected;
  - an unreadable file is reported `access-denied`, never `not-found`.
- [x] The runner:
  - passes arguments through `ArgumentList`;
  - refuses a shell start;
  - kills the process tree at its limit;
  - propagates cancellation;
  - bounds stdout;
  - closes stdin.
- [x] The script is exactly the allowlisted commands and contains no memory-display, extension-load, script or shell
  command.
- [x] Parser fixtures cover:
  - a normal dump;
  - 0x1E;
  - symbol failure;
  - an unresolved module;
  - PnP available and PnP absent;
  - malformed or incomplete output, including a forged marker;
  - KD non-zero exit;
  - timeout;
  - DumpChk reporting a corrupt dump;
  - DumpChk absent;
  - a partial small dump.
- [x] Output stays within 32 KiB, with deterministic truncation.
- [x] Without the capability, the tool is absent from the catalog. The Windows provider contributes it and the Linux
  provider does not.
- [x] The catalog tests are platform-aware and the constraint snapshot is regenerated.
- [ ] Real-dump validation on the operator machine after deployment. Not done; CI cannot access the dump.
- [ ] Follow-up: replace the synthetic fixtures with sanitized real captures, then decide on XML (`-xml -xmi -xcs -xmf`).
- [ ] Follow-up: consider a per-tool timeout declaration (ADR-0048 §10).
