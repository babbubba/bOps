## Outcome

Expose delegation to the operator from the CLI (ADR-0030 section 9).

## Checklist

- [x] `bops delegate "<objective>"` and `bops delegate status|resume|cancel|reconcile <id>`; the existing `bops "<goal>"` keeps working unchanged.
- [x] Composition root: build `PolicyRoleProfileSource` over the same loaded `PolicyConfig` the policy engine comes from (`LoadPolicyEngineAsync` returns only the engine today), and register it as the `IRoleProfileSource` with the `DelegationRunner` (V1.2-D). A broken `policy.yaml` is `AllForbidden` and has no profile, so a delegation start must end `Denied` on the `Profile` dimension; test that here.
- [x] Human approval prompt: a console `IPlanApprovalProvider` (the SDK contract D added), showing the plan hash, the plan's steps, the findings and the reduced authority. The runtime refuses a decision that does not come from a human identity.
- [x] Clear exit codes and messages for denied, cancelled, requires-reconciliation and completed states.
- [x] Tests drive the real CLI against a fake model provider.

## Definition of Done

- [x] An operator can start, approve, resume and reconcile a delegation from the terminal.

## Interpretations made in I

None changes an ADR.

1. **Every subcommand uses the full composition.** `status`, `cancel` and `reconcile` do not need a model, but they share the composition
   with `start` and `resume`, so a valid `ModelProvider` section is needed to run any of them. A usage error ends before anything is composed.
2. **`cancel` reaches a stored run, not a live process.** It ends a run a crash left `Running` (`DelegationRunner.CancelAsync`): audited,
   human only, refused for a run waiting for reconciliation (which `reconcile` settles). A run executing in a live process is cancelled with Ctrl+C
   in it, which ends it as `Cancelled` and is reported like any other end. There is no cross-process signal.
3. **`reconcile` does not resume.** `--accept` marks the unsettled steps done and returns the run to `Running`; `resume` then continues it,
   and puts any steps left to a human. `--abandon` ends it.
4. **The administrator role is not enforced by the CLI.** A person at the terminal is the trust anchor, as for `bops vault rotate-key`. The runtime still
   refuses a decider that is not a human identity, and the API (V1.2-J) enforces the role.
5. **The authority shown is the one the change will run under, as it stands.** The Remediation envelope is computed for the approval, and again
   when the role starts, so its deadline is counted from then; every other dimension is the same, and a test compares them.
6. **The diagnosis-only run asks nobody.** With no change named there is no plan to approve; the run ends `DiagnosisCompleted`, exit 0.
7. **Delegation state is one SQLite file next to the others.** `Delegation:FilePath`, `delegations.db` by default, like `Memory:FilePath` and `Audit:FilePath`.
