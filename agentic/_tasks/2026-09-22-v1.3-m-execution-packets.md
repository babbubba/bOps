# V1.3-M — execution packets: neutral entitlement and plugin lifecycle

Parent task: `2026-09-16-v1.3-oss-entitlement-plugin-lifecycle.md`
Execution strategy: `../_plans/2026-09-22-v1.3-coding-agent-execution.md`
Dependency: V1.3-L complete; repository-topology gate closed.

M changes public contracts, execution authorization placement and plugin lifecycle. It is therefore
split more aggressively than G–L. Coding agents must not implement the whole batch in one session.

The public repository owns only product-neutral contracts and lifecycle mechanics. Community,
commercial, pricing, SKU, vendor token formats, signed entitlement-provider implementation and
Coordinator/account business rules remain outside `bOps`.

## M1 — entitlement ADR: architecture only

**Preferred model:** Terra Medium while available.
**Fallback:** Sol Low.
**No implementation in this packet.**

### Read first
- parent M task;
- `01-architecture-rules.md`, especially A1/A3/A5/A7/A10/A11;
- `03-security-rules.md`;
- `05-workflow.md`;
- ADR-0016 post-action verification;
- ADR-0025 restricted invocation;
- ADR-0030/0031 delegation/envelope;
- `AgentRunner.cs` and the narrow execution path around policy/approval/verification;
- existing audit authorization events/contracts.

Do not broadly scan packages.

### ADR must decide, without commercial vocabulary
1. neutral entitlement request/decision shapes;
2. provider interface boundary and lifetime;
3. exact enforcement point: after policy/approval validity and immediately before execution;
4. re-evaluation for verification/read inspection;
5. fail-closed cases for an **entitlement-governed subject**;
6. how standalone OSS operation remains usable when no official-distribution entitlement applies;
7. validity/time/clock-skew contract;
8. resource/feature/node/capability/Skill/version/target constraints;
9. audit fields that expose decision/source/reason but never token/license contents;
10. what happens to already-running work if entitlement state changes.

### Mandatory distinction
"Provider missing" cannot globally disable standalone Apache-licensed bOps. The ADR must define an
explicit neutral applicability/governance boundary: absence/failure fails closed **only where an
entitlement requirement applies**, while unrelated standalone OSS capabilities remain independent as
required by the parent task.

If the existing architecture cannot express that distinction without a new public concept, document
it in the ADR instead of inventing a product tier.

### Stop
Return the Proposed ADR and list any unresolved operator decisions. Do not implement M2 until ADR is
accepted.

## M3 — runtime entitlement enforcement

**Model:** Luna Medium.
**Escalation:** Terra Medium for a precise execution-ordering blocker.

### Read first
Accepted M1 ADR, M2 contracts, `AgentRunner` execution path, policy/approval tests, verification tests,
delegation execution tests.

### Implementation rule
Add the smallest runtime integration accepted by M1.
Do not name package/tool/provider products in core.

The entitlement decision must be checked at the execution point prescribed by the ADR, after the
approval/policy prerequisites that bind intent and before side effect execution.

### Test first
At minimum:
- entitled side effect executes;
- governed request denied -> tool never executes;
- entitlement revoked after human approval but before execution -> tool never executes;
- provider failure for governed request -> fail closed;
- not-applicable/unrelated standalone OSS path behaves exactly as ADR says;
- verification/read inspection remains available as accepted by ADR;
- audit records category/decision/reason without secret material;
- delegation path cannot bypass entitlement;
- resume/retry cannot reuse a stale entitlement decision.

Do not alter risk or approval semantics to integrate entitlement.

## M8 — OSS leak/security/release gate

**Implementation model:** Luna Medium.
**Final review:** Sol Low.

### OSS leak scan
Architecture/repository tests must reject public-tree occurrences of private product/business
identifiers selected by the accepted ADR/task, including:
- Community/commercial tier logic;
- prices/SKUs/payment providers;
- private token/license formats or keys;
- commercial DBA prompts/playbooks/fixtures;
- private Coordinator/Portal implementation.

The scan must avoid false positives against documentation that explicitly states exclusions; prefer
targeted directories/patterns rather than an unusably broad word blacklist.

### Entitlement security matrix
Run all parent-task cases:
valid, expired, future, revoked, wrong subject/installation/feature/Skill/version/capability/node/
target, resource exhaustion, missing/failing provider, cache/offline, clock rollback,
post-approval revocation.

### Plugin lifecycle matrix
Run M5/M6 attack and concurrency suites plus UI tests.

### Final validation
- public API compatibility/version evidence;
- Release build;
- full non-live suite;
- Angular clean install/build/headless tests;
- Windows/Linux CI;
- docs/ADR/task/HANDOFF aligned.

### Sol Low review scope
Review only:
- entitlement bypass;
- stale approval/entitlement race;
- audit secret leakage;
- plugin archive/trust bypass;
- last-known-good failure;
- authorization/CSRF/idempotency/concurrency;
- public/private dependency direction.

Do not add features during review.

### M Definition of Done
The public repo contains a neutral entitlement enforcement hook and safe local plugin lifecycle
mechanics, while standalone OSS remains independent where entitlement is not applicable and no
commercial implementation/business rule leaks into `bOps`.
