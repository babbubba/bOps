## I1 — Firewall.Core contracts and normalization

**Model:** Luna Medium.

### Read first
- parent I task;
- `bOps.Packages.Network.Native.Core` argument/result patterns;
- shared conformance patterns;
- architecture rule A8.

### Create
`bOps.Packages.Firewall.Core` with:
- manifests;
- typed filters/argument validation;
- DTOs/output formatting;
- normalized protocol/direction/action/profile representations;
- deterministic rule-id helper contract;
- bounds/truncation;
- shared conformance tests.

No native firewall calls in Core.

### Normalization rules
- direction: inbound/outbound/unknown;
- action: allow/block/unknown;
- protocol: tcp/udp/icmp/any/native-unknown;
- port expressions normalize only when lossless;
- addresses normalize only when lossless;
- preserve bounded `unparsedCondition` when native semantics exceed the normalized schema;
- any unknown condition that may affect matching forces `complete:false`.

### Caller bounds
- limit default 500/max 5000;
- maxOutputBytes default 65536/max 262144;
- out-of-range filters are rejected, never silently clamped.

### Tests
Pure fixtures for filtering, deterministic ordering, byte/row bounds, id stability, unknown-expression
semantics and shape conformance.

## I2 — Windows firewall collector

**Model:** Luna Medium. Escalate only isolated COM interop issues to Terra Medium while available.

### Native recipe
Use Windows Firewall COM/API:
- `HNetCfg.FwPolicy2` / `INetFwPolicy2`;
- rule interfaces exposed by that API.

No PowerShell, `netsh`, registry scraping or shell.

### firewall.status
Report domain/private/public profiles separately.
Do not collapse profile disagreement into one boolean without preserving profile detail.

### firewall.rules
Map only fields with authoritative API evidence:
- name/enabled/direction/action/protocol;
- local/remote addresses and ports;
- profiles;
- application/service/interface;
- native ordering/priority when exposed.

Use deterministic observation id derived from stable native identity/normalized fields if no durable
native id exists. Document it as read-only observation identity.

### firewall.rule.inspect
Resolve id against a fresh bounded enumeration; do not accept a hidden native expression from caller.

### Tests
Real read-only enumeration on windows-latest:
- status parses;
- every row matches manifest contract;
- filters are deterministic;
- inspect round-trips a listed id;
- permission/API failures produce incomplete/unavailable evidence, not fake empty-complete.

## I3 — Linux nftables collector

**Model:** Luna Medium.

### Native recipe
Preferred source is fixed:
`nft -j list ruleset`

Use `ProcessStartInfo.ArgumentList`, no shell, no caller-controlled raw expression.

Parse JSON, not human output.

### Mapping
Normalize:
- family/table/chain;
- base-chain hook/direction;
- policy;
- protocol;
- addresses;
- ports;
- action;
- interfaces;
- rule handle/order where present.

If a rule contains expressions that cannot be represented losslessly:
- retain bounded `unparsedCondition`;
- set result/source completeness false;
- never claim the rule does or does not match a packet.

### Tests
Deterministic nft JSON fixtures:
IPv4, IPv6, sets/ranges, interface matches, unknown expression, multiple tables/backends, base-chain
policy.

Where CI permits, use a disposable namespace/container fixture with a real nft ruleset.

## I4 — Linux iptables fallback/additional evidence

**Model:** Luna Medium.

### Native recipe
Fixed direct:
- `iptables-save`;
- `ip6tables-save`.

No shell and no arbitrary arguments.

### Backend semantics
- nft only -> nft backend;
- iptables only -> iptables backend;
- both active with potentially overlapping policy -> expose both and `complete:false` warning;
- no supported backend -> unavailable/incomplete, not firewall-disabled certainty.

Parse common chains/rules only. Preserve unknown extension matches as bounded unparsed evidence.

### Tests
Fixtures for:
- default policies;
- TCP/UDP ports;
- IPv6;
- multiport/ranges where lossless;
- extension/unknown matches;
- dual-backend ambiguity.

## I5 — integration, architecture, docs and CI

**Model:** Luna Low/Medium.

### Required diagnostic join
Document/test the expected evidence sequence:
`network.dns_query -> network.routes -> network.sockets -> firewall.status/rules -> network.port_check`.

Do not add `firewall.evaluate`.
Do not add any firewall mutation tool.

### Architecture guard
Add/extend a test proving no first-party manifest introduces:
- firewall add/remove/change/enable/disable;
- raw firewall expression execution;
- generic shell/process execution.

### Validation
Run Firewall Core/platform/conformance + Architecture targeted tests, then one full Release build and
non-live suite. Windows/Linux CI must both pass.
