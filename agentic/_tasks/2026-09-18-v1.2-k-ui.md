## Outcome

Let an operator follow and control a delegation from the dashboard (ADR-0030 section 9). V1.1-F was revised from medio to alto during implementation; revisit this effort if the same happens.

## Checklist

- [x] Delegations list and detail: roles in order, reduced authority, evidence and findings, plan hash and approval prompt, verification verdict, journal and any ambiguity awaiting reconciliation.
- [x] Reconcile and cancel actions visible only to the permitted role.
- [x] Untrusted output rendered with the existing safe-text rules.
- [x] Component and store tests plus the production build.
- [x] New UI text goes through the translation catalogues of [`the multilingual UI task`](2026-09-19-ui-multilanguage-it-en.md) once it has landed (it should land first); if this task lands first, its strings are added to the catalogues when that task migrates the UI.

## Definition of Done

- [x] The dashboard shows the whole delegation lifecycle and never exposes secrets.

## Interpretations made in K

None changes an ADR.

1. **English literals.** The multilingual UI task has not landed, so the new strings are English text in the template and component; they join
   the catalogues when that task migrates the UI (this task's own instruction for that order).
2. **Polling, not a stream.** Like the approval queue, the view polls every two seconds; the API offers no stream for delegations.
3. **Waiting for a plan is `Running` plus a flag.** The view shows a plan waiting from the API's `awaitingPlanApproval`, because the runtime
   never writes `DelegationStatus.AwaitingApproval` (see V1.2-J).
4. **The pending-plan list is read only for approvers.** Anyone else sees "Waiting for an approver" and no buttons; the API would refuse them anyway.
5. **No confirmation dialog on reconcile.** The banner states the consequence and each button says what it does; a confirmation step can be added
   with the translations if the operator wants one.
