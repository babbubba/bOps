# V1.3-G — service configuration and scheduled-work diagnostics

Status: **future; starts only after V1.3-F**

Repository: `bOps`

## Outcome
Go beyond service running/stopped state and expose how a service is configured, what it depends on, whether it starts automatically and what scheduled automation may affect the host.

## Service additions
Add to ServiceToolManifests with Windows/Linux implementations.

### service.config — Read
Parameter `name`.
JSON: `exists,name,displayName,description,executable,arguments,workingDirectory,user,startupType,enabled,restartPolicy,dependencies,dependents,source,complete`.
startupType enum: automatic, automatic-delayed, manual, disabled, static, unknown.

Windows:
- ServiceController where sufficient.
- SCM P/Invoke `OpenSCManager/OpenService/QueryServiceConfig/QueryServiceConfig2` for binary path, account, start type, delayed auto start, failure actions.

Linux:
- fixed direct `systemctl show <unit> --property=...` via ArgumentList.
- Properties: FragmentPath, ExecStart, User, Group, WorkingDirectory, UnitFileState, Restart, Requires, Wants, After, Before.

### service.dependencies — Read
Parameter name, optional direction=both|requires|dependents, limit.
Return normalized relation + service name + known status.

### service.enable / service.disable — Medium
One service only. Windows uses ChangeServiceConfig start type. Linux uses fixed direct `systemctl enable/disable -- <unit>`. No mask/unmask. Verification through service.config confirms enabled true/false. Do not start/stop the service implicitly.

## Scheduler package
Create Scheduler.Core, Scheduler.Windows, Scheduler.Linux.

### scheduler.list — Read
Optional source=all|task-scheduler|systemd-timer|cron, limit default 200/max 2000.
Rows: `id,name,source,enabled,schedule,nextRunUtc,lastRunUtc,lastResult,target,user`.

### scheduler.inspect — Read
Parameter stable id from list. Return enabled/schedule/times/result/target/user/workingDirectory/description/triggerSummary/complete. Never credentials.

### scheduler.history — Read
Parameters id, sinceMinutes default 1440/max 10080, limit default 100/max 1000.
Newest-first rows: timestampUtc,event,result,message.

### scheduler.enable / scheduler.disable — Medium
Supported only for Windows Task Scheduler and systemd timers. Cron stays read-only in this batch. Verify through scheduler.inspect.

## Windows scheduler
Use Task Scheduler 2.0 COM API. Enumerate folders recursively with limits; task path is stable id. History comes from Microsoft-Windows-TaskScheduler/Operational filtered to task path/name, without raw XML dump.

## Linux scheduler
- systemd timers: fixed direct systemctl list-timers/show.
- cron inventory: /etc/crontab, /etc/cron.d, cron.hourly/daily/weekly/monthly and readable user spool.
- Parse standard five-field cron and @daily/@hourly/etc.; unsupported syntax => schedule:null + warning.
- history: journald where available; otherwise complete:false.
Never execute scheduled target command text.

## Validation
Real test-owned Windows service/task and Linux unit/timer; cron parser fixtures; service enable/disable verification; scheduler mutation refusal for cron; bounded output and no credential leakage.

## Definition of Done
bOps can explain service startup/dependency/restart behavior and diagnose scheduled automation failures with typed evidence.
