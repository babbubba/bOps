# V1.1-G — writable Settings and encrypted local vault

Status: **planned**
Recommended model effort: **molto alto**
Repository: `bOps`
Depends on: V1.1-F complete; V1.0 auth and secret-reference contracts

## Outcome

Persist provider selection and provider API-key insert/update from the local UI without exposing
secret plaintext or breaking existing CLI environment/user-secret configuration.

## ADR decisions required before code

- [ ] Specify the versioned vault envelope, standard AEAD primitive, nonce/tag handling and key size
      using supported .NET cryptography; no custom cipher or home-grown KDF.
- [ ] Specify master-key bootstrap from an external environment/service secret, fail-closed startup,
      rotation, backup/restore, corruption handling and recovery. The master key is never written
      beside the vault.
- [ ] Specify atomic file replacement, locking/concurrent writers, crash recovery and restrictive
      Windows/Linux permissions.
- [ ] Specify configuration precedence among explicit environment values, encrypted vault, legacy
      user-secrets and committed empty defaults.
- [ ] Specify masking for keys shorter than ten characters so prefix/suffix never overlap; the API
      never reads plaintext merely to render a mask.
- [ ] Specify audit events and reason codes without secret values or reversible fingerprints.

## Test-first backend work

- [ ] Add cryptographic known-answer/round-trip tests and tamper/wrong-key/truncation/version tests.
- [ ] Implement a host-owned encrypted `ISecretProvider`/writer extension without adding
      cryptographic dependencies to `bOps.Abstractions` unless an ADR explicitly requires it.
- [ ] Store ciphertext plus minimal metadata; keep `first6...last4`, presence and timestamps as
      separate display metadata captured at write time.
- [ ] Zero/dispose transient buffers where practical; never include plaintext in exceptions,
      `ToString`, structured logs, telemetry or audit.
- [ ] Implement versioned, validated, atomic non-secret provider-selection storage separately.
- [ ] Add administrator-only endpoints to read safe Settings state and set/replace/clear provider
      secret references and active provider selection.
- [ ] Validate provider IDs against the registry and reject lost-update races with version/ETag or
      the ADR-selected concurrency mechanism.
- [ ] Audit actor, setting name, operation, provider and outcome only.

## Angular work

- [ ] Add provider selection with current/effective-source indication and save conflict handling.
- [ ] Add write-only key input for create/replace, required mask display, clear confirmation and
      success/error states; never prefill a secret field.
- [ ] Keep API/session credentials and provider secrets out of localStorage/sessionStorage and URL.
- [ ] Require re-entry for updates; clipboard reveal/copy of stored plaintext does not exist.

## Validation

- [ ] Authorization tests: Viewer/Operator/Approver cannot mutate Settings; Administrator can.
- [ ] Secret scanning and capture tests across API responses, logs, audit, telemetry, exceptions and
      browser storage.
- [ ] Restart tests prove persistence; precedence tests prove explicit environment override behavior.
- [ ] Concurrent write, crash during replace, wrong master key, rotation and restore tests.
- [ ] Real Windows/Linux permission tests where the platform exposes a reliable primitive.
- [ ] CLI compatibility tests prove existing environment/user-secret flows still work.
- [ ] Release build, full .NET suite, Angular production/headless tests and cross-platform CI.
- [ ] Document initial provisioning, master-key rotation, backup/recovery and headless deployment.

## Definition of Done

- [ ] Provider selection and secrets survive restart and remain administratively manageable.
- [ ] No endpoint or UI can retrieve stored plaintext.
- [ ] Vault corruption/tampering/missing master key fails closed without silent data loss.
- [ ] Legacy CLI configuration remains compatible and precedence is documented/tested.
