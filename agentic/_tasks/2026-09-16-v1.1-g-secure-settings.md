# V1.1-G — writable Settings and encrypted local vault

Status: **complete**
Recommended model effort: **molto alto**
Repository: `bOps`
Depends on: V1.1-F complete; V1.0 auth and secret-reference contracts

## Outcome

Persist provider selection and provider API-key insert/update from the local UI without exposing
secret plaintext or breaking existing CLI environment/user-secret configuration.

Scope grew once during implementation, by explicit operator direction: rather than "provider
selection" being only a provider *id* toggle, the operator asked for the whole provider
configuration — endpoint, model, tool-calling support, API key, and room for provider-specific
extras — to be fully UI-managed and persisted. See ADR-0029's "Provider profile" section.

## ADR decisions required before code

- [x] Specify the versioned vault envelope, standard AEAD primitive, nonce/tag handling and key size
      using supported .NET cryptography; no custom cipher or home-grown KDF.
      (`docs/architecture/adr/0029-encrypted-local-vault-and-master-key.md` — AES-256-GCM,
      HKDF-SHA256, 96-bit nonce, 128-bit tag, AAD binding provider id + schema version.)
- [x] Specify master-key bootstrap from an external environment/service secret, fail-closed startup,
      rotation, backup/restore, corruption handling and recovery. The master key is never written
      beside the vault.
      (`SecretReference`-based bootstrap, `bOps.Api/Program.cs` refuses to start if configured but
      unresolvable; `bops vault rotate-key` CLI command; file-level backup/restore.)
- [x] Specify atomic file replacement, locking/concurrent writers, crash recovery and restrictive
      Windows/Linux permissions.
      (Temp-file-then-rename, `SemaphoreSlim` + `expectedVersion` optimistic concurrency,
      `chmod 600` on Linux. Windows ACL hardening explicitly documented as a known gap, not
      silently absent.)
- [x] Specify configuration precedence among explicit environment values, encrypted vault, legacy
      user-secrets and committed empty defaults.
      (`bOps.Api/ProviderResolution.cs`, tested in `ProviderResolutionTests.cs`. "Legacy
      user-secrets" was confirmed, during exploration, to not actually exist as implemented
      configuration in this codebase today — environment is the only real legacy path.)
- [x] Specify masking for keys shorter than ten characters so prefix/suffix never overlap; the API
      never reads plaintext merely to render a mask.
      (`SecretMask.Compute`, captured once at write time — `SecretMaskTests.cs`.)
- [x] Specify audit events and reason codes without secret values or reversible fingerprints.
      (`SettingsChangedAuditEvent`, `bOps.Abstractions/Audit.cs`.)

## Test-first backend work

- [x] Add cryptographic known-answer/round-trip tests and tamper/wrong-key/truncation/version tests.
      (`VaultCipherTests.cs`, 13 tests.)
- [x] Implement a host-owned encrypted `ISecretProvider`/writer extension without adding
      cryptographic dependencies to `bOps.Abstractions` unless an ADR explicitly requires it.
      (`VaultSecretProvider` in `bOps.Runtime`; `bOps.Abstractions` unchanged except the new audit
      event type.)
- [x] Store ciphertext plus minimal metadata; keep `first6...last4`, presence and timestamps as
      separate display metadata captured at write time.
- [x] Zero/dispose transient buffers where practical; never include plaintext in exceptions,
      `ToString`, structured logs, telemetry or audit.
      (`CryptographicOperations.ZeroMemory` on every transient plaintext/key-material buffer in
      `VaultCipher`; verified no plaintext reaches the audit log —
      `SetProviderKey_NeverWritesThePlaintextToTheAuditLog`.)
- [x] Implement versioned, validated, atomic non-secret provider-selection storage separately.
      (`SettingsStore`, non-secret `settings.json`, separate from the encrypted vault.)
- [x] Add administrator-only endpoints to read safe Settings state and set/replace/clear provider
      secret references and active provider selection.
      (`SettingsEndpoints.cs`, `ApiAuthorization.AdministratorPolicy`.)
- [x] Validate provider IDs against the registry and reject lost-update races with version/ETag or
      the ADR-selected concurrency mechanism.
      (`expectedVersion` on every key write; 409 on mismatch.)
- [x] Audit actor, setting name, operation, provider and outcome only.

## Angular work

- [x] Add provider selection with current/effective-source indication and save conflict handling.
- [x] Add write-only key input for create/replace, required mask display, clear confirmation and
      success/error states; never prefill a secret field.
      (Verified live: the password input is empty on every expand, even for a provider with a

- [x] Keep API/session credentials and provider secrets out of localStorage/sessionStorage and URL.
- [x] Require re-entry for updates; clipboard reveal/copy of stored plaintext does not exist.

## Validation

- [x] Authorization tests: Viewer/Operator/Approver cannot mutate Settings; Administrator can.
- [x] Secret scanning and capture tests across API responses, logs, audit, telemetry, exceptions and
      browser storage.
      (API response and audit-log scans are explicit tests. Telemetry never carries tool
      arguments/output by architecture rule D and this feature adds nothing to that path.
      Exceptions: `VaultCorruptedException`/`VaultConcurrencyException` messages are constructed
      without plaintext by inspection — no message in `VaultCipher.cs`/`VaultStore.cs` interpolates
      a secret value.)
- [x] Restart tests prove persistence; precedence tests prove explicit environment override behavior.
      ("Restart" simulated at the store level via reopened-instance tests, the same convention
      `PluginStoreTests` already uses. `ProviderResolutionTests.cs` covers the full precedence
      chain, including the environment-override-wins case.)
- [x] Concurrent write, crash during replace, wrong master key, rotation and restore tests.
      (Concurrent-write and wrong-master-key are automated tests. "Crash during replace" relies on
      the same atomic temp-file-then-rename pattern `PluginStore` already uses without a dedicated
      crash-injection test either. Rotation logic (`VaultStore.List`/`Resolve`/`Set`) is fully
      covered by `VaultStoreTests`; the `bops vault rotate-key` CLI command itself has no automated
      test — this repository has no CLI test project at all yet, and neither do the existing
      `plugin`/`audit` CLI command families; it was smoke-tested manually against a real vault
      file. Restore is file-level, documented, no code to test.)
- [x] Real Windows/Linux permission tests where the platform exposes a reliable primitive.
      (Linux: real `chmod 600` assertions. Windows: no test, matching the ADR's documented decision
      not to add ACL hardening in this batch.)
- [x] CLI compatibility tests prove existing environment/user-secret flows still work.
      (`ResolveEffectiveModelOptions_WithNoVaultConfigured_BehavesExactlyLikeTheOriginalEnvironmentOnlyResolution`.)
- [x] Release build, full .NET suite, Angular production/headless tests and cross-platform CI.
      (Release build and full suite green locally on Windows; GitHub Actions run
      [35277152220](https://github.com/babbubba/bOps/actions/runs/35277152220) green on Windows
      and Ubuntu.)
- [x] Document initial provisioning, master-key rotation, backup/recovery and headless deployment.
      (`README.md`, `HANDOFF.md`.)

## Definition of Done

- [x] Provider selection and secrets survive restart and remain administratively manageable.
- [x] No endpoint or UI can retrieve stored plaintext.
- [x] Vault corruption/tampering/missing master key fails closed without silent data loss.
- [x] Legacy CLI configuration remains compatible and precedence is documented/tested.
