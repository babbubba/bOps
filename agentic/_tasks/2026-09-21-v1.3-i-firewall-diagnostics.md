# V1.3-I — firewall posture and rule diagnostics

Status: **future; starts only after V1.3-H**
Recommended model effort: **medio**
Repository: `bOps`
Depends on: V1.3-H complete

## Outcome
Add enough firewall visibility to explain connection failures. Mutation is intentionally excluded until stable rule identity, rollback and lockout-prevention semantics exist.

## Package layout
Create Firewall.Core/Windows/Linux plus conformance/platform tests.

## Tools
### firewall.status — Read
Return `enabled,defaultInbound,defaultOutbound,profiles,backend,source,complete`.
Windows reports domain/private/public profiles separately. Linux reports active nftables/iptables backends and base-chain policies; multiple backends => complete:false warning.

### firewall.rules — Read
Filters: direction=all|inbound|outbound, action=all|allow|block, protocol=all|tcp|udp|icmp|any, localPort, remotePort, enabled, limit default 500/max 5000, maxOutputBytes default 65536/max 262144.
Rows: `id,name,enabled,direction,action,protocol,localAddresses,remoteAddresses,localPorts,remotePorts,profiles,application,service,interface,priorityOrOrder,source`.
Unknown complex native expressions become bounded `unparsedCondition` and complete:false.

### firewall.rule.inspect — Read
Parameter id exactly as returned by rules. Return one normalized rule plus bounded native detail needed for troubleshooting. If backend lacks stable persistent id, observation id may be deterministic hash of normalized chain/table/native handle; document that it is not a mutation token.

## Windows
Use Windows Firewall COM/API (`HNetCfg.FwPolicy2` / INetFwPolicy2 and rule interfaces), not PowerShell.

## Linux
1. Prefer fixed direct `nft -j list ruleset`, parse JSON.
2. Fallback/additional evidence from fixed direct `iptables-save` / `ip6tables-save`.
No shell and no raw expression supplied by model.
Normalize common addresses/protocols/ports/interfaces/order; preserve unknown conditions honestly.

## Cross-tool diagnostic join
Document expected path: network.dns_query -> network.routes -> network.sockets -> firewall.rules -> network.port_check.
Do not implement a firewall.evaluate simulator claiming perfect packet-filter evaluation.

## Validation
Real Windows read-only enumeration; disposable Linux nft namespace/container fixture; parser fixtures for nft JSON/iptables-save/IPv6/port ranges/unknown expressions; deterministic filters/bounds; architecture test proves no firewall mutation tool.

## Definition of Done
bOps can expose host firewall state and relevant rules for a failing connection with honest backend/completeness semantics.
