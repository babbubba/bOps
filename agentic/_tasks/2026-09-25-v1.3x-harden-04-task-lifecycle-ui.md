## Objective

The operator always sees a coherent task state transition and the correct next action: the Dashboard
follows a resumed task to completion, never stops watching on a stale snapshot, reconnects after
transient failures, and offers only the actions the server says are possible.

## Confirmed defects addressed

- **C-05 (frontend)** `TasksStore.resume()` → `watch()` immediately; `watchTaskEvents.poll()` stops on
  the first non-`Running` snapshot (the stale pre-resume one).
- **C-12 (frontend)** no Cancel in UI or API client; Resume hidden for `Running`, so an orphaned task is
  a dead end.
- **C-19** body-less 503 (duplicate resume or capacity) shown as "Impossibile raggiungere l'API di
  bOps".
- Resume button shown for every status except `Running`/`Completed` (`dashboard.html:118`), no in-flight
  disabling; watcher gives up permanently after 8 transient failures with no reconnect.

## Source finding IDs

F-03 (frontend), F-04 (frontend), F-06 (frontend), F-19.

## Scope

1. **Watcher state machine** (`core/streaming/task-events.ts`): accept `expectedAttempt`; a snapshot
   with a lower attempt is stale and never ends the watch; end only on a terminal status with attempt ≥
   expected, or 404; transient errors (0/429/502/503/504) never stop the watch permanently — expose a
   `reconnecting` state with capped backoff and `Retry-After`; resume polling on `online` and
   `visibilitychange`; 401 → `sessionExpired` state (HARDEN-10 later restores the session; until then
   route to login and restore the watch afterwards).
2. **Resume flow** (`state/tasks.store.ts`): use the 202 body snapshot (from HARDEN-3) as the selected
   task immediately; set `expectedAttempt`; disable the button while the request is in flight.
3. **Actions from server fields:** render Resume only when `resumable`; otherwise show
   `resumeBlockedReason`; render **Cancel** when `executing`; show "Interrupted" when
   `status=Running && !executing`. No policy logic duplicated in Angular.
4. **Cancel** wired to `DELETE /api/agents/tasks/{id}` in `bops-api-client.ts`.
5. **Error mapping** (`state/describe-error.ts`): map by status and body `code`: 409 (already running,
   not resumable, role task → "resume the delegation run"), 503 with body ("bOps is busy; retry in N
   s"), provider failure kinds from HARDEN-2 ("check provider key in Settings", "provider rejected the
   request: …"), unreachable only for status 0 or a gateway error without a bOps body.
6. **Task detail**: show attempt, terminal reason and tokens used when present.
7. i18n keys in `en.ts` and `it.ts` for every new state and message.
