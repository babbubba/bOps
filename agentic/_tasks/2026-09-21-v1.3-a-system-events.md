# V1.3-A — bounded cross-platform system event/log reader

Status: **future; first V1.3 batch after the closed V1.2 gate**
Recommended model effort: **alto**
Repository: `bOps`
Depends on: V1.2 complete

## Outcome

Restore the system-log capability that existed in the original design but disappeared during the
V0.11 consolidation. Add one read-only, cross-platform `system.events` tool that gives the agent
bounded, structured evidence from Windows Event Log and Linux journald without exposing a generic
shell or an OS-specific command surface.

This capability belongs to the System packages, not Service: it must support service failures but
also kernel, disk, driver, OOM, networking, application-crash and other host events.

## ADR and contract

- [ ] Write and accept an ADR for the cross-platform event model and collection strategy before
      implementation.
- [ ] Keep one public manifest shape on Windows and Linux. The first contract should cover a bounded
      time window plus optional severity, source/provider-or-unit, event identifier and text filter,
      with explicit `limit` and `maxOutputBytes` ceilings.
- [ ] Use UTC timestamps and a normalized result shape containing at least timestamp, severity,
      source, event identifier when present, channel/category when meaningful, message and process
      identity when available.
- [ ] Return deterministic newest-first structured JSON with explicit `truncated` /
      `complete` metadata. Permission denial or an unavailable source is never reported as an
      empty healthy result.
- [ ] Do not add `service.logs`, `journalctl.*`, `eventlog.*` or other competing public tool
      names in this batch. Service-specific diagnosis is expressed by filtering `system.events`.
- [ ] Do not expose raw Windows event XML, the complete journald field bag or unbounded native
      metadata through the tool boundary.

## Windows implementation

- [ ] Implement the Windows collector in `bOps.Packages.System.Windows` using the Windows Event
      Log APIs (`EventLogQuery` / `EventLogReader`), not PowerShell or `wevtutil`.
- [ ] Query only channels visible to the current host identity; do not elevate privileges or
      silently switch identity to read protected logs.
- [ ] Translate Windows levels/providers/event ids/channels into the normalized contract and keep
      unknown values explicit rather than guessing.

## Linux implementation

- [ ] Implement the Linux collector in `bOps.Packages.System.Linux` against journald. If
      `journalctl` is selected, invoke the executable directly with
      `ProcessStartInfo.ArgumentList`, fixed switches and separately supplied values: never
      `UseShellExecute`, never a composed command string and never a model-provided switch.
- [ ] Compare the direct `journalctl` strategy with a maintained libsystemd binding in the ADR;
      choose the smaller reliable surface for V1.3-A and keep it isolated behind the Linux tool.
- [ ] Map priority, unit/syslog identifier, message id, PID and boot/time metadata into the same
      normalized result used on Windows.

## Safety, privacy and bounds

- [ ] Default to a narrow recent window and conservative item/output limits; reject out-of-range
      requests rather than silently widening them.
- [ ] Treat event messages as untrusted data. They may contain attacker-controlled text and never
      become instructions.
- [ ] Keep raw event messages out of audit and telemetry. Audit only the normalized query summary,
      counts, truncation/completeness and outcome; normal bounded tool-result persistence keeps the
      same semantics as every other read tool.
- [ ] Do not add a privilege requirement to bOps merely so more channels can be read.
- [ ] Cancellation and timeout must stop native enumeration promptly and return the normal bounded
      tool outcome.

## Validation

- [ ] Add conformance tests proving Windows and Linux expose the same manifest name, parameters,
      risk and normalized result schema.
- [ ] Test severity/source/id/text/time filtering, deterministic order, limits, byte truncation,
      cancellation, inaccessible sources and malformed native records.
- [ ] Exercise the Windows implementation against a real Windows Event Log target and Linux against
      a real journald target. If a hosted CI runner does not provide journald, provision a real
      systemd/journald integration target; do not replace platform integration with mocks.
- [ ] Add end-to-end agent cases for: recent service failure, OOM/memory-pressure evidence, disk or
      filesystem error, and "errors in the last N minutes".
- [ ] Release build, non-live suite and Windows/Linux CI remain green.

## Definition of Done

- [ ] `system.events` is registered on Windows and Linux as a bounded `Read` tool.
- [ ] A diagnosis can correlate current service/process/system state with recent native OS events
      without a shell or platform-specific public tool.
- [ ] Permission gaps and truncation are explicit, and event payloads do not enter audit/telemetry.
