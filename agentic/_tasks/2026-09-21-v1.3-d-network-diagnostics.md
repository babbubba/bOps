# V1.3-D — sockets, routes and network diagnostics

Status: **implemented (2026-09-22); PR open, CI pending (evidence below)**
Recommended model effort: **medio**
Repository: `bOps`
Depends on: V1.3-C complete

## Outcome
Add senior network troubleshooting evidence while preserving current Network tools. Create OS-specific native companions instead of overloading the BCL-only package.

## Package layout
Create `bOps.Packages.Network.Native.Core`, `.Windows`, `.Linux`, conformance tests and platform tests. CLI/API register existing `bops.packages.network` plus exactly one native package.

## Tools
### network.sockets
Optional filters: `protocol=all|tcp|udp`, `state`, `pid`, `localPort`, `limit` default 500/max 5000.
Rows: `protocol,addressFamily,localAddress,localPort,remoteAddress,remotePort,state,pid,processName`.
UDP remote/state null where meaningless. Permission-limited PID mapping stays null with incomplete source status.

### network.routes
Optional `addressFamily=all|ipv4|ipv6`, `limit`.
Rows: `destination,prefixLength,gateway,interfaceName,interfaceIndex,metric,addressFamily,protocol`.
Keep existing `network.route` unchanged as simple default-gateway/connected-subnet summary.

### network.neighbors
Optional family/interface/limit. Rows: `ip,mac,interfaceName,state,addressFamily`.

### network.interface_stats
Optional `sampleMilliseconds` default 500/max 5000 and interface filter.
Rows: rates for bytes/packets, receive/send errors and drops, speedMbps, operationalStatus. Unsupported counters are null, not zero.

### network.dns_query
Parameters: `name`, `recordType=A|AAAA|PTR`; optional `server`, timeout default 3000/max 10000.
System resolver uses BCL. Explicit server uses a minimal typed DNS UDP client for only A/AAAA/PTR; no raw query type/class/options. Return answers, TTL where direct, resolver/server and elapsed ms; max 100 answers.

### network.traceroute
Parameters host, maxHops default 30/max 64, timeout default 1000/max 5000, addressFamily auto/ipv4/ipv6.
Implement using Ping with increasing TTL/hop-limit; no tracert/traceroute executable. One probe per hop in first version.

### network.ntp_probe
Parameters host + timeout default 2000/max 5000. One SNTP/NTP request over UDP/123. Return server/local UTC, estimated offset, RTT, stratum/version validity. Reject malformed/unsynchronized replies. Read-only.

## Windows
- sockets: `GetExtendedTcpTable/GetExtendedUdpTable`.
- routes: `GetIpForwardTable2`.
- neighbors: `GetIpNetTable2`.
- interface counters: `GetIfEntry2` or equivalent BCL counters.
Process name lookup is best-effort with Process.GetProcessById.

## Linux
- sockets: parse `/proc/net/tcp,tcp6,udp,udp6`; map socket inode→PID by bounded scan of visible `/proc/<pid>/fd`.
- routes/neighbors: direct fixed `ip -j ...` invocations with ArgumentList, no shell/model switches.
- interface stats: `/proc/net/dev` + `/sys/class/net`.

## Validation
Real loopback TCP/UDP tests prove PID/port ownership. Route/neighbor tests assert schema only. DNS parser gets malformed/compression-pointer tests. Traceroute must terminate on destination/hop/timeout. NTP parser uses deterministic packet fixtures plus opt-in live smoke. All outputs/calls bounded and cancellable.

## Definition of Done
bOps can map ports to processes, inspect full routing/neighbor state, interface health, deliberate DNS, path hops and clock offset.

### What could not be verified here, and why

- **Every Linux collector path.** This is a Windows development machine; `LinuxSocketCollector`,
  `LinuxRouteCollector`/`LinuxNeighborCollector` (the two fixed `ip -j` invocations) and
  `LinuxInterfaceStatsCollector` never ran against a real `/proc` or a real `ip` binary here -- the 11
  `[LinuxOnlyFact]` tests skip visibly. The `ubuntu-latest` CI job is their evidence. The Windows P/Invoke
  path (the byte-offset `SOCKADDR_INET` parsing in `WindowsRouteCollector`/`WindowsNeighborCollector`,
  and the owner-PID table parsing in `WindowsSocketCollector`) **was** verified for real on this machine,
  including against real loopback sockets proving exact PID/port ownership -- the highest-risk, most
  novel part of this batch.
- **The `network.ntp_probe` live smoke test** (`[Trait("Category","LiveModel")]`, against
  `pool.ntp.org`) was written but not run in this evidence pass, by design -- it is excluded from the
  default CI filter and is allowed to be flaky against a real internet server.
- **A privileged Linux run** where `network.sockets` can map every process's sockets without a
  `pidMappingComplete: false` gap. The unprivileged path (this identity cannot list another user's
  `/proc/<pid>/fd`) is what `LinuxSocketCollector` is written for and what the conformance suite's
  schema assertions accept either outcome for; neither this machine nor a typical CI runner exercises
  the privileged branch specifically.

### Residual and known limitations

- `network.routes`/`network.neighbors`' `interfaceIndex` is resolved from `NetworkInterface`'s own
  index lookup by name; an interface the native table reports that has no matching `NetworkInterface`
  entry (rare -- a just-removed interface) reports index `0`, documented in ADR-0035 as the "unknown"
  sentinel rather than a nullable field, to keep the row shape identical across platforms.
- `network.routes`' Windows `protocol` field maps a known subset of `NL_ROUTE_PROTOCOL` codes to names
  (`local`, `netMgmt`, `icmp`, `rip`, `ospf`, `bgp`, `autoStatic`, `static`, `other`); an unlisted code
  is reported as its numeric string rather than failing the row.
- `network.dns_query` reports `ttlSeconds: null` for every answer from the system resolver -- the BCL
  `Dns` class does not expose it; only the explicit-`server` path (the hand-written UDP client) reports
  a direct TTL.
- `network.traceroute` sends one probe per hop, as the task spec specifies for this version; a hop with
  transient loss is reported as `"timeout"` rather than retried.
