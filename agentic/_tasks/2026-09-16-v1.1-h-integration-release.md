## Integration checklist

- [x] Verify all required ADRs are accepted and no implementation contradicts their consequences.
      ADR-0023 through ADR-0029 exist and are accepted; the architecture test (rule A1) plus a scan
      of `bOps.Runtime`/`Policy`/`Memory`/`Audit` found no package, tool or provider name, and no
      `shell.run`/`system.exec`/`process.start` tool exists anywhere in `src/`, `samples/` or
      `tests/`.
- [x] Review `bOps.Abstractions` API diff against 1.0 and confirm intended SemVer/version metadata.
      Reflection dump of the public surface at the V1.0 close-out commit (`891dae2`) against the
      current build: **zero removed or changed members**, additions only (Skill/Capability/Evidence/
      ExecutionPlan contracts, `SettingsChangedAuditEvent`, additive properties on existing audit
      events and `PolicyContext`, `ToolManifest.RequiresExplicitApproval`,
      `ToolParameterType.PathList`). `1.1.0-preview.1` is therefore a correct minor-additive
      version; the final `1.1.0` is set at tag time.
- [x] Exercise one workflow combining system/device evidence, Web research and a sample Skill without
      granting any Web/file/plugin/settings shortcut around policy. Composed from three parts, none
      of which bypasses the governed path: `V11ReleaseGateTests.SystemEvidenceThenWebResearch_…`
      drives the real API composition through `system.info` then `web.fetch` (unsafe loopback
      destination denied by policy, both outcomes audited, `web.search` invisible while
      unconfigured); `SkillExecutionTests` covers the sample Skill's restricted invoker (same-package
      Read tools only — a Skill cannot reach `web.*` or any non-Read tool), exact approval, execution
      and independent verification. There is no single test that chains a real model, Web and an
      installed Skill; that composition was not exercised and is not claimed.
- [x] Exercise large filesystem preview and permanent deletion through API/UI with hash-bound
      approval and post-verification. `PermanentDeletionApproval_RequiresAcknowledgement_AndUsesPagedScopedPreview`
      covers the paged preview, missing-acknowledgement rejection, hash-bound approval, deletion,
      post-verification and a name-free audit summary. The UI leg is covered by the Angular unit
      tests, not by a browser run in this batch.
- [x] Exercise plugin catalog and Settings with every API role and restart persistence.
      `V11ReleaseGateTests` runs each of `viewer`/`operator`/`approver`/`administrator` on its own
      against `/api/plugins` and `/api/settings` (roles are independent claims, not a hierarchy),
      proves the catalog exposes no mutation route, and boots a second host on the same state
      directory and vault master key to show profile, key mask and active provider survive a real
      restart without the key ever appearing in a response or in `vault.dat`.
- [x] Verify output/history/audit budgets across the new high-cardinality capabilities.
      **Finding, resolved:** the committed `src/core/bOps.Api/appsettings.json` had drifted from the
      documented and CLI defaults in `55d9585` (V1.1-F) — `Filesystem:ReadPatterns` was
      `["*","c:\**"]`, `Inventory:MaximumEntries` `900000`, `MaximumOutputBytes` `131072`. The
      committed file is back to the safe defaults (no readable paths, `100000`, `32768`); the wider
      local values now live in the git-ignored `appsettings.Development.json`, which ASP.NET loads
      automatically under the Development profile. A deployment that wants `fs.size`/inventory over
      real paths must set `Filesystem:ReadPatterns` explicitly. Per-tool bounds themselves (Web
      body/decompression caps, inventory contract tests, name-free deletion audit summary) pass.
