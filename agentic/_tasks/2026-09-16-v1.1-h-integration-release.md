# V1.1-H — integration, documentation and release gate

Status: **planned**
Recommended model effort: **alto**
Repository: `bOps`
Depends on: V1.1-A through V1.1-G complete

## Outcome

Validate V1.1 as one coherent public release rather than a collection of locally green batches.

## Integration checklist

- [ ] Verify all required ADRs are accepted and no implementation contradicts their consequences.
- [ ] Review `bOps.Abstractions` API diff against 1.0 and confirm intended SemVer/version metadata.
- [ ] Exercise one workflow combining system/device evidence, Web research and a sample Skill without
      granting any Web/file/plugin/settings shortcut around policy.
- [ ] Exercise large filesystem preview and permanent deletion through API/UI with hash-bound
      approval and post-verification.
- [ ] Exercise plugin catalog and Settings with every API role and restart persistence.
- [ ] Verify output/history/audit budgets across the new high-cardinality capabilities.

## Full validation

- [ ] `dotnet build bOps.slnx --configuration Release` with zero warnings.
- [ ] `dotnet test bOps.slnx --configuration Release --no-build --filter "Category!=LiveModel"`.
- [ ] Angular clean install, production build and headless unit tests.
- [ ] Windows/Linux CI including real platform package tests.
- [ ] Package/SDK pack and sample-plugin/Skill installation smoke tests.
- [ ] Architecture, secret, license/header, documentation-link and obsolete-path scans.
- [ ] Negative security suite for SSRF, destructive preflight drift, vault leakage and package trust.

## Documentation and release evidence

- [ ] Update README tool/roadmap/status sections, CHANGELOG, HANDOFF, API/OpenAPI and SDK docs.
- [ ] Ensure no active document points to archived plans/specifications/tasks as authority.
- [ ] Record exact pass/skip counts and platform-gated checks; do not describe unrun tests as passed.
- [ ] Prepare release notes, SBOM/provenance inputs and compatibility/upgrade notes.
- [ ] Obtain explicit authorization before any tag, push, publication or release creation.

## Definition of Done

- [ ] Every V1.1 task is complete with durable evidence.
- [ ] The sample Skill, all new tools, UI flows and security boundaries pass cross-platform gates.
- [ ] Documentation and version metadata agree on the exact state.
- [ ] V1.2 has not started before this gate closes.
