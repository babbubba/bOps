## Required end-to-end scenarios
1. **DB port 5432/1433 unreachable**: network.dns_query -> network.routes -> network.sockets -> firewall.status/rules -> service.status/config -> system.events -> network.port_check. Distinguish no listener, bind, route/DNS, firewall evidence, service failure. Never infer remote firewall state.
2. **Service keeps crashing**: service.status/config/dependencies -> system.events -> system.crashes -> process.tree/metrics -> storage.io -> system.memory/swap.
3. **DB/application became slow**: system.cpu -> memory -> swap -> process.metrics -> storage.io -> storage.health -> system.events -> network.interface_stats. Document that DB Skill then adds DB-native waits/locks/query stats.
4. **File cannot be replaced/deleted**: fs.stat -> fs.permissions -> fs.locks -> process.inspect/tree/modules.
5. **TLS connection fails**: network.dns_query -> network.routes -> network.port_check -> network.tls_probe -> certificate.inspect -> system.time -> network.ntp_probe.
6. **Scheduled job did not run**: scheduler.inspect/history -> identity.* -> service.status/config -> system.events -> fs.permissions where relevant.
7. **Host needs reboot/update regression**: system.reboot_pending -> system.update_history -> system.updates -> system.events -> system.drivers.
8. **Docker-hosted service failure**: docker.containers/inspect/logs -> docker.images -> network.sockets -> storage.io -> system.events.

Use fake/recorded model responses for planner determinism; pair with real platform package fixtures where required.

## Commercial Skill foundation
Document minimum host evidence before a DB Skill concludes root cause:
- CPU/memory/swap/process metrics;
- disk latency/queue/health + filesystem capacity;
- listener/PID/route/firewall/TLS;
- service identity/config;
- recent OS events/crashes/updates;
- time/clock evidence for auth/TLS.
Commercial Skills remain responsible for typed DB tools such as postgres.stat_activity/locks/vacuum and sqlserver.wait_stats/blocking/query_store. No arbitrary SQL.
