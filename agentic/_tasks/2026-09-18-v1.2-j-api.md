## Interpretations made in J

None changes an ADR.

1. **`AwaitingApproval` is not written by the runtime.** A run waiting for its plan is `Running`. The API reports `awaitingPlanApproval`
   from its own queue rather than change the runtime here; making the runtime write the status is a separate decision (it also changes
   what a crash leaves behind and what `resume` accepts).
2. **A start returns once the run is stored.** The id is given out after the store holds the run (or the start finished), so an idempotent
   repeat can return the earlier run's id instead of a dangling one.
3. **Live cancel is audited twice.** The runner records the run's end under its operator; the API adds a terminal event under whoever
   asked. Cancelling a stored run a crash left `Running` goes through `DelegationRunner.CancelAsync`, which audits the canceller itself.
4. **No four-eyes.** An identity with both `operator` and `approver` can approve its own plan. Left as documented residual risk.
5. **The approver is always `api-user`.** The runtime still refuses an agent, the runtime or one of the run's agent ids; the API cannot
   produce those, so that refusal is proved by the Runtime tests, not again here.
