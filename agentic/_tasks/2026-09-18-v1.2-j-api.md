# V1.2-J — API surface

Status: **planned**
Recommended model effort: **alto**
Repository: `bOps`
Depends on: V1.2-I complete
Governing ADR: `docs/architecture/adr/0030-privilege-reducing-multi-agent-delegation.md`

## Outcome

Expose delegation through authenticated HTTP endpoints (ADR-0030 section 9) and extend the authorization matrix and threat model.

## Checklist

- [ ] Failing tests first for authentication, role checks and idempotent start.
- [ ] Endpoints to start, list, read, cancel, resume and reconcile; start/cancel/resume need the operator role, reconcile the administrator role.
- [ ] Composition root: build `PolicyRoleProfileSource` over the same loaded `PolicyConfig` as the policy engine (`LoadPolicyEngine` returns only the engine today), register it as the `IRoleProfileSource` with the `DelegationRunner` (V1.2-D), and test that a broken `policy.yaml` ends a delegation as `Denied` on the `Profile` dimension.
- [ ] Approval reuses the existing human approval path and rejects any non-human approver: an approval-queue `IPlanApprovalProvider` (the SDK contract D added) beside `ApiApprovalProvider`, answered only by an authenticated human principal.
- [ ] Responses never include secrets or unredacted tool output; streaming or polling follows the existing task pattern.
- [ ] Update `docs/security/threat-model.md` for the new surface and the inter-agent data flow.

## Definition of Done

- [ ] The API cannot start, approve or reconcile without the required human role.
- [ ] Threat model and API documentation are updated.
