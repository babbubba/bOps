# V1.1-E — Web search and fetch capabilities

Status: **planned**
Recommended model effort: **molto alto**
Repository: `bOps`
Depends on: V1.1-D complete; configured test SearXNG instance

## Outcome

Create a first-party Web package with bounded `web.search` backed by operator-configured SearXNG
and hardened `web.fetch`, both returning untrusted external evidence as Risk `Read` results.

## ADR and threat model delta

- [x] Write an ADR for the first generic package that makes arbitrary outbound network requests.
- [x] Model SSRF, DNS rebinding, redirect chains, internal/metadata endpoints, malicious content,
      decompression bombs, charset confusion, oversized streams and prompt injection.
- [x] Define endpoint configuration/trust for SearXNG; do not hard-code or silently select a public
      instance.
- [x] Define URL policy for fetch: HTTP/HTTPS only, normalized host/port, DNS/IP validation before
      connect and after every redirect, deny loopback/link-local/multicast/unspecified/private ranges
      by default, and make any operator allowlist explicit and narrow.
- [x] Define maximum redirects, connect/overall timeout, compressed/decompressed bytes, result text,
      content types and search result count.

## `web.search`

- [x] Add the package/project/manifest following the existing package boundary; no Web identity in
      Runtime, Policy, Memory or Audit.
- [x] Implement the documented SearXNG `/search` JSON contract with bounded query, language,
      category, safe-search, time-range and page inputs only where supported.
- [x] Detect JSON-disabled instances and return an actionable structured failure; never scrape HTML
      as fallback.
- [x] Normalize result title, URL, snippet, source engines and published date when supplied; never
      invent missing metadata.
- [x] Deduplicate and deterministically order results within the source response while preserving
      relevance ordering semantics documented by the adapter.

## `web.fetch`

- [x] Use a dedicated bounded `HttpClient` pipeline with no ambient credentials, cookies, proxy
      credentials or caller-supplied arbitrary headers.
- [x] Revalidate every redirect target; cap redirect count and reject scheme changes outside policy.
- [x] Stream and stop at size limits; never buffer an unbounded body.
- [x] Support an explicit small allowlist of textual media types; binary/unsupported content returns
      metadata and a bounded diagnostic rather than arbitrary bytes.
- [x] Return requested/final URL, status, content type/encoding, retrieval timestamp, truncation and
      bounded text. Neutralize tool-output delimiters under S5.

## Tests and validation

- [x] Recorded contract tests for SearXNG success, empty, malformed, JSON-disabled, timeout and
      limited responses; opt-in live smoke test against an operator-provided instance.
- [x] Local malicious-server tests for redirect to loopback/private/metadata, DNS change, oversized
      body, compressed bomb, invalid charset, slow stream and hostile prompt-like content.
- [x] Policy/output-budget/audit tests prove content is data, not instruction, and is never placed in
      telemetry attributes.
- [ ] Package discovery and platform compatibility tests on Windows and Linux.
- [ ] Release build, non-live suite and cross-platform CI are green.
- [x] Document SearXNG JSON enablement, endpoint setup, network policy and known limitations.

## Definition of Done

- [x] Search works without an API key against a configured JSON-enabled SearXNG endpoint.
- [x] Fetch cannot reach denied network ranges or exceed bounded resources in the tested threat model.
- [x] External content is attributed, bounded, sanitized as tool data and audited safely.
