# V1.1-D — governed recursive and batch permanent deletion

Status: **complete**
Recommended model effort: **molto alto**
Repository: `bOps`
Depends on: V1.1-C exact immutable inventory complete

## Outcome

Add a permanent High-risk recursive/batch deletion whose approval is cryptographically bound to the
exact target set while remaining usable for thousands of files.

## Non-negotiable behavior

- Tool name is `fs.delete_tree`; existing single-file `fs.delete` keeps its semantics.
- Every execution requires approval and a fresh, complete `DeletionManifest`.
- The approved hash covers canonical roots, every entry and identity metadata, total bytes/counts,
  traversal semantics, creation/expiry and node/task context.
- No deletion occurs when enumeration is incomplete, over a hard ceiling, expired or stale.
- Permanent means permanent: no recycle-bin/trash promise and no implied rollback.

## ADR and contract

- [x] Write an ADR covering preflight state, canonical encoding/hash, expiry/retention, TOCTOU
      checks, approval binding, partial completion, verification and audit representation.
- [x] Define batch-root overlap/deduplication and reject ambiguous globs or path patterns.
- [x] Select configurable safe ceilings only after measured scale tests; the design must support at
      least 10,000 files while guaranteeing finite work.
- [x] Define cursor-based manifest APIs and authorization so only the entitled actor/task can browse
      or approve the exact list.
- [x] Define status transitions: building, ready, approved, executing, partially completed,
      verified, refuted, inconclusive, expired and rejected.
