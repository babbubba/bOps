## Outcome

Implement envelope reduction and enforce it before policy in the single execution path (ADR-0030 section 3).

## Read first

`2026-09-18-v1.2-b-contracts.md`, sections "Interpretations made while writing the contracts" and "Open
question for V1.2-C" (now resolved by ADR-0031), then ADR-0031 in full.

## Decisions taken (2026-09-19, D-027)

The operator chose, and `agentic/06-decisions.md` D-027 records:

1. **A per-role requirement table.** Each envelope dimension is required (empty is `DelegationDenied`),
   optional (empty means nothing permitted) or not applicable (forced to empty or zero) for each role.
   Least privilege by construction, and an exhausted token budget cannot block an approved plan.
2. **A new ADR-0031** amends ADR-0030 §3, because `agentic/05-workflow.md` forbids editing an accepted ADR to
   change its meaning. ADR-0030 gets an `Amended by ADR-0031` pointer on acceptance.
3. **Profile contracts in the SDK.** A role profile, the operator's authority request and a read-only source
   interface go in `bOps.Abstractions` (`1.2.0-preview.2`); `bOps.Policy` implements the source from
   `policy.yaml`, so `bOps.Runtime` still does not reference `bOps.Policy`.

Two things ADR-0031 makes explicit beyond the table, for the operator to review before accepting it:
grant versus exhaustion (§3: a budget granted as zero is a denial, running out mid-run is
`BudgetExceeded`/`DeadlineExceeded` as in ADR-0030 §6), and what an envelope can enforce per step (§4: tools
declare no target, so targets and environments are matched only for steps that carry a skill scope, and a
non-Read step without one is denied in a delegated run).

## Checklist

- [ ] ADR-0031 accepted by the operator; `Amended by ADR-0031` pointer added to ADR-0030. Nothing below is enforced before this.
- [ ] SDK contracts for the role profile, the authority request and the profile source (names fixed here), with round-trip tests (A2), `bOps.Abstractions` at `1.2.0-preview.2`, and a public-surface diff that compares enum values as well as names.
- [ ] Failing tests first, table-driven over every role and every dimension: required and empty is denied, optional and empty is allowed, not applicable is forced empty, and a profile that grants a not-applicable value is malformed.
- [ ] Failing tests first: a child never broadens capability, tool, target, environment, risk, blast radius, window, budget or deadline.
- [ ] An empty required dimension is `DelegationDenied`, audited with role and dimension, never a default. Exhaustion after start is not a denial (ADR-0031 §3; reservation stays in V1.2-E).
- [ ] Enforce the envelope in `ExecuteStepAsync` before `IPolicyEngine.Evaluate`: tool, risk ceiling and window at execution, plus skill, capability, target, environment and blast radius for a step with a skill scope. The more restrictive of envelope and policy wins; `Critical` stays Forbidden.
- [ ] A delegated step with no envelope is rejected, and a delegated step above `Read` with no skill scope is denied (ADR-0031 §4).
- [ ] Add the optional `delegation` section of `policy.yaml` (loader rejects malformed input including a not-applicable grant; a missing role profile denies; `SafeDefault` has none). This part is mechanical and may run at effort **alto** once ADR-0031 is accepted and the reduction tests exist.
- [ ] Envelope fields are placed in the contextual `PolicyContext` and audit; `IPolicyEngine` semantics are unchanged.

## Definition of Done

- [ ] Property-style tests show reduction is monotone in every dimension, including the forced values.
- [ ] No path executes a tool for a delegated agent without passing the envelope.
- [ ] The stated limit (targets and environments are not matched for plain Read calls) is recorded for the V1.2-L threat model.
