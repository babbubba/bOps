# V1.2-C — authority reduction and envelope enforcement

Status: **planned**
Recommended model effort: **molto alto**
Repository: `bOps`
Depends on: V1.2-B complete
Governing ADR: `docs/architecture/adr/0030-privilege-reducing-multi-agent-delegation.md`

## Outcome

Implement envelope reduction and enforce it before policy in the single execution path (ADR-0030 section 3).

## Checklist

- [ ] Failing tests first: a child never broadens capability, tool, target, environment, risk, blast radius, window, budget or deadline.
- [ ] An empty intersection in any dimension is `DelegationDenied`, audited, never a default.
- [ ] Enforce the envelope in `ExecuteStepAsync` before `IPolicyEngine.Evaluate`; the more restrictive of envelope and policy wins; `Critical` stays Forbidden.
- [ ] A delegated step with no envelope is rejected.
- [ ] Add the optional `delegation` section of `policy.yaml` (loader rejects malformed input; a missing role profile denies; `SafeDefault` has none).
- [ ] Envelope fields are placed in the contextual `PolicyContext` and audit; `IPolicyEngine` semantics are unchanged.

## Definition of Done

- [ ] Property-style tests show reduction is monotone in every dimension.
- [ ] No path executes a tool for a delegated agent without passing the envelope.
