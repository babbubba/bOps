## Outcome

Guarantee that no role approves or verifies its own work (ADR-0030 section 5).

## Checklist

- [x] D already builds the Verification role deterministically and refuses an approval whose identity is an agent, the runtime or one of the run's own agents (`DelegationRunner`, `AgentRunner.VerifyPlanAsync`): for each verifiable step it reads the system itself through its own envelope and asks the tool's evaluator what that fresh reading means, and D's tests show the reading differs from Remediation's. G's job is what is left: the guarantees stated as their own tests and the cases D's construction does not cover (a run with a repeated agent identity, the approval contract's edge cases, verification when the plan has several steps with mixed verdicts), plus reviewing the rule with the operator.
- [x] Failing tests first: an agent identity presented as approver is rejected; a run with a repeated agent identity is invalid; Verification cannot consume Remediation's result as proof.
- [x] Verification gathers its own Read evidence from the approved plan hash and expected end state and evaluates the declared `VerificationSpec`; the verdict is deterministic with no model call.
- [x] `Inconclusive`, `Refuted` and `NotApplicable` never end a run as success (S4).
- [x] `IApprovalProvider` is never invoked for an agent; documented and covered by tests.

## Definition of Done

- [x] No role can approve or verify its own action.
- [x] Verification remains independent of Remediation by construction and by test.

## Interpretations made in G

None changes an ADR.

1. **Where the rule is enforced.** The ADR names the plan approval; G enforces the same rule at every approval a delegated run
   can put to a human, which is the step-level one. In a run that is not delegated nothing changes.
2. **A refusal is a rejection.** An approval from an identity that is not a human is turned into `Approved = false` before it
   is audited, so the audit trail shows a refusal with the identity that claimed to approve, and the run ends `Rejected`.
   An agent that says no is a no like any other.
3. **What an agent can be recognised by.** Its kind (`agent`), the runtime's kind (`system`), or an id equal to one of the
   agents the run created before the asking one, or to the asking one. An `IApprovalProvider` that lets an agent through
   under another kind and another id cannot be told from a person; that is for the surface that authenticates the approver
   (V1.2-I, V1.2-J).
4. **Verification's independence is by construction and by test.** `VerifyPlanAsync` takes the approved plan, its hash, the
   actor and the Verification agent's scope; nothing Remediation produced. A test of the signature fails if a parameter is
   ever added through which a result could reach it. The runtime's own check right after a step is Remediation's and is
   a separate reading; the verdict of the run is Verification's.
5. **A step nobody can verify is not confirmed.** A plan step that is not a Read and whose tool is not registered, or
   declares no verification, makes the verdict `Inconclusive`.

## For the operator

The checklist item "reviewing the rule with the operator" needs a decision that is not the runtime's to make:

- The runtime accepts the operator who started a run as the approver of its plan, because they are a human and the ADR asks
  for a human. If a second person must approve (four eyes), that is a policy on who may approve, not a property of the
  pipeline. It is not built. Say if you want it, and it belongs with the approval surface in V1.2-I and V1.2-J.
