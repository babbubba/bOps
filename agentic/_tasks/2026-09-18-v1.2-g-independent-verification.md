# V1.2-G — independent verification and separation of duties

Status: **planned**
Recommended model effort: **molto alto**
Repository: `bOps`
Depends on: V1.2-F complete
Governing ADR: `docs/architecture/adr/0030-privilege-reducing-multi-agent-delegation.md`

## Outcome

Guarantee that no role approves or verifies its own work (ADR-0030 section 5).

## Checklist

- [ ] D already builds the Verification role deterministically and refuses an approval whose identity is an agent, the runtime or one of the run's own agents (`DelegationRunner`, `AgentRunner.VerifyPlanAsync`): for each verifiable step it reads the system itself through its own envelope and asks the tool's evaluator what that fresh reading means, and D's tests show the reading differs from Remediation's. G's job is what is left: the guarantees stated as their own tests and the cases D's construction does not cover (a run with a repeated agent identity, the approval contract's edge cases, verification when the plan has several steps with mixed verdicts), plus reviewing the rule with the operator.
- [ ] Failing tests first: an agent identity presented as approver is rejected; a run with a repeated agent identity is invalid; Verification cannot consume Remediation's result as proof.
- [ ] Verification gathers its own Read evidence from the approved plan hash and expected end state and evaluates the declared `VerificationSpec`; the verdict is deterministic with no model call.
- [ ] `Inconclusive`, `Refuted` and `NotApplicable` never end a run as success (S4).
- [ ] `IApprovalProvider` is never invoked for an agent; documented and covered by tests.

## Definition of Done

- [ ] No role can approve or verify its own action.
- [ ] Verification remains independent of Remediation by construction and by test.
