# V1.2-D — deterministic orchestrator and role profiles

Status: **planned**
Recommended model effort: **alto**
Repository: `bOps`
Depends on: V1.2-C complete
Governing ADRs: `docs/architecture/adr/0030-privilege-reducing-multi-agent-delegation.md`, amended in §3 by
`docs/architecture/adr/0031-per-role-envelope-requirements.md`

## Outcome

Run the fixed Discovery, Diagnostic, approval, Remediation, Verification pipeline over the existing paths (ADR-0030 sections 2 and 4).

## Checklist

- [ ] Failing tests first with a fake model and fake tools: happy path, malformed delegation, no plan (diagnosis only), approval rejected, denied step.
- [ ] `DelegationRunner` in `bOps.Runtime`; roles are profiles from configuration, not hard-coded products; the core names no package or tool (A1).
- [ ] Discovery and Diagnostic reuse the existing loop and restricted invoker through a tool view filtered by the envelope; no second loop or second authorization path. V1.2-C2 added the delegated entry points (`RunDelegatedAsync`, `PrepareDelegatedSkillAsync`, `ExecuteDelegatedPreparedSkillAsync`), which enforce the envelope but still offer the model every registered tool: narrowing `GetAvailableManifests()` by the role's envelope is D's.
- [ ] Remediation executes exactly the approved plan hash with no model call; a plan/approval mismatch stops before the first step.
- [ ] Inter-agent values are structured Evidence/Finding/ExecutionPlan/VerificationReport only, delivered as delimited data (S5); every Finding cites Evidence.
- [ ] Roles cannot request delegation; depth is fixed and any other depth is rejected.
- [ ] Build each role's scope with `DelegatedExecutionScope.For(delegationId, agent, envelope)` and reach the runner only through the delegated entry points. The public `RunAsync`, `PrepareSkillAsync` and `ExecutePreparedSkillAsync` are never delegated, so a role that used one would run unrestricted: the C2 enforcement cannot catch that, so a test must show every event of every role carries the correlation block.
- [ ] Derive the root envelope with the V1.2-C1 reduction at the start and each role's envelope from it, write a `DelegationEnvelopeAuditEvent` for every reduction and every refusal, and end a refused delegation as `DelegationStatus.Denied` before any model call. The reduction only returns the result; the orchestrator audits it.
- [ ] Before asking for a role's envelope, check the run's remaining budget and deadline and end the run as `BudgetExceeded` or `DeadlineExceeded` (ADR-0031 §3, with V1.2-E). Never hand the reduction an exhausted parent to be refused as a denial.
- [ ] Before asking the operator to approve a prepared plan, check that Remediation's envelope would allow every step (tool, risk, blast radius, target, environment). A plan that is certain to be denied is rejected up front instead of being approved and then refused.

## Definition of Done

- [ ] One objective crosses the four roles deterministically with fakes.
- [ ] Skill, policy, approval and verification paths are reused unchanged.
