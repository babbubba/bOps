# V1.3-F — filesystem troubleshooting helpers

## Context and objective

Extend the existing `bOps.Packages.Filesystem` family with bounded diagnostic tools for text
search, file tails, permissions and locking, plus governed single-file copy and directory creation.
All filesystem access continues to use `FilesystemPathPolicy` immediately before I/O.

## Constraints

- Do not change `bOps.Abstractions` or the execution/policy model.
- Never follow symlinks or reparse points while traversing for content diagnostics.
- All reads and output are bounded; regex matching has a timeout.
- `fs.copy` and `fs.mkdir` are verifiable non-Read tools, with no overwrite behaviour.
- Windows and Linux source collection is real and visibly platform-gated where necessary.

## Affected areas

- `bOps.Packages.Filesystem` tools, options, provider and hosts.
- Filesystem package test suite and operator documentation.
- V1.3 roadmap, task tracking, README, CHANGELOG and HANDOFF.

## Implementation strategy

1. Add bounded shared utilities and manifests for `fs.grep`, `fs.tail`, `fs.permissions`,
   `fs.locks`, `fs.copy`, `fs.copy.verify` and `fs.mkdir`.
2. Reuse the established resolved-path policy at every direct filesystem touch; make copy
   re-resolve both endpoints before opening/renaming and clean only its invocation-owned temp file.
3. Add guarded Windows ACL/Restart Manager and Linux mode/procfs implementations.
4. Cover limit, encoding, binary, regex timeout, path policy, verification and platform facts.
5. Validate locally, then use Windows/Linux CI as the authoritative platform evidence.

## Completion criteria

The task definition's tool, bounds, path-safety and verification requirements are implemented,
documented, tested, and merged only after both CI platforms pass.
