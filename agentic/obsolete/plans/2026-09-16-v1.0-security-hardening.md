# V1.0 security hardening and stable public contract

## Context

V0.11 is complete and present on `main`/`origin/main`. The V1.0 milestone in
`piano-bops-v0.9.1-v2.0.md` is the next open gate. The baseline on 2026-09-16 is a warning-free
Release build and a green non-live test suite on Windows. The only pre-existing working-tree item
is the untracked user file `specifiche-pendenti.md`; it is outside this plan and must remain
untouched.

## Objective

Make the local runtime, API, plugin loader and `bOps.Abstractions` SDK suitable for a 1.0 release
candidate: authenticated and authorized API calls, channel-derived actor identities, referenced
local secrets, verified plugin provenance, bounded HTTP execution, operator-visible audit
verification, tested recovery, and reproducible release evidence.

## Constraints

- Preserve rules A1-A12 and S1-S11 in `agentic/`; no generic execution surface.
- Keep execution local-only and do not introduce V1.1 Skill/Capability contracts.
- `bOps.Abstractions` remains dependency-free and every public member is documented.
- Core changes are test-first. Platform code continues to use real-target tests.
- In-process plugins remain trusted code; signatures establish provenance, not sandboxing.
- Secrets may be resolved only at the host boundary and must never enter prompts, audit, logs,
  telemetry or reports.
- Do not commit, push or modify the user's untracked `specifiche-pendenti.md`.

## Affected areas

- `bOps.Abstractions`, Runtime, Audit, Memory, PluginHost, CLI and API.
- Provider packages and their recorded HTTP contract tests.
- Angular local UI authentication and authenticated SSE transport.
- CI/release workflows, security/plugin documentation, README, CHANGELOG and HANDOFF.

## Dependencies

- V0.11 closure (`14ad49e` and preceding tranche commits).
- Existing V0.3 audit chain, V0.7 resumable task store and V0.10 plugin loader.
- ADR-0020 for the package activation/trust boundary.

## Risks

- Freezing an accidental contract defect into `bOps.Abstractions` 1.0.
- Treating a package signature as an isolation boundary.
- Leaking API/model keys through DTOs, URLs, logs or browser persistence.
- Duplicate task starts under retries or concurrent requests.
- Restoring a stale approval after restart without a live authenticated approver.
- Platform-specific file-permission and release reproducibility differences.

## Implementation strategy

1. Record the 1.0 contract/security decisions in an ADR and write the complete threat model.
2. Add a dependency-free secret-reference/provider contract and host-side environment provider;
   replace committed API-key values with secret references.
3. Add API-key authentication, role policies and principal-derived `ActorIdentity`; update the UI
   to keep the credential in memory and use authenticated HTTP/SSE requests.
4. Add bounded rate/concurrency controls, idempotent task start, task cancellation and selective
   transient provider retries.
5. Add detached package signatures, a local publisher trust store, install-time provenance and a
   fail-closed enable policy for unverified packages.
6. Expose audit-chain verification through the CLI and harden local state-file permissions.
7. Add deterministic malformed-input/fuzz, tampering, authorization, concurrency and recovery
   tests, then freeze/document `bOps.Abstractions` as 1.0.0.
8. Add deterministic packaging/SBOM/provenance workflow and align operator/developer docs.

## Validation strategy

- Targeted tests after every core boundary change.
- `dotnet build bOps.slnx --configuration Release`.
- `dotnet test bOps.slnx --configuration Release --no-build --filter "Category!=LiveModel"`.
- `npm ci`, Angular production build and headless unit tests.
- `dotnet pack` for the SDK and deterministic publish/package smoke checks.
- Secret-pattern and core/package-name architecture scans.
- CI on Windows and Linux remains the authoritative real-platform gate.

## Completion criteria

- Threat model and ADR accepted in-tree and consistent with implementation.
- Anonymous API access is denied; roles gate reads/actions/approvals; approver identity comes only
  from the authenticated principal.
- Model/API credentials are configured by reference and resolved locally without observability
  leakage.
- Unsigned/untrusted plugins cannot be enabled; verified provenance is inspectable.
- Task starts are bounded/idempotent, cancellation is observable, transient retries are bounded,
  and restart recovery has an executable test.
- Audit verification is operator-accessible and state files are permission-hardened where the OS
  provides a portable primitive.
- SDK version is 1.0.0 with documented/round-tripped public surface.
- Release candidate artifacts, SBOMs, hashes and provenance are reproducible on Windows/Linux.
- README, CHANGELOG, HANDOFF and task tracking match the validated repository state.
