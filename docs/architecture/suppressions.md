# Suppressions

Every suppression beyond the shared list in `Directory.Build.props` is recorded here, per
[`agentic/02-coding-standards.md`](../../agentic/02-coding-standards.md): rule id, scope,
reason, and the condition under which it can be removed.

| Rule | Scope | Reason | Remove when |
|---|---|---|---|
| `CA1720` | `bOps.Abstractions.ToolParameterType` (enum) | The analyzer flags identifier names that contain a type name (`String`, `Integer`, `Boolean`). For a JSON-Schema-like parameter type enum these are exactly the correct, most legible names — renaming to dodge the rule (e.g. `Text`, `WholeNumber`) would make the contract worse to read. | Never — this is a permanent, considered suppression, not a placeholder. |
| `CA1720` | `bOps.Abstractions.BlastRadius` (enum) | Same reasoning as `ToolParameterType` above — `Single` is the analyzer-flagged member (it contains `System.Single`'s type name by coincidence, not by using the type) and is exactly the right word for "affects one target" (ADR-0023); renaming it to dodge the rule would make the contract worse to read. | Never — this is a permanent, considered suppression, not a placeholder. |
| `CA2007` | Solution-wide (`Directory.Build.props`) | `ConfigureAwait(false)` protects library code from deadlocking a capturing `SynchronizationContext` (WinForms, WPF, classic ASP.NET). bOps is a console host plus libraries consumed only by that host and its own tests — no such context exists anywhere in the solution, so the diagnostic cannot catch a real bug here; it was firing on 66 call sites when `AnalysisLevel` escalated to `latest-all` at V0.3. | If a host that runs under a capturing context is ever added (unlikely — no such host is on the roadmap). |
| `CA1054` / `CA1056` | `bOps.Abstractions.ChatModelOptions.BaseUrl` (constructor parameter and property) | The analyzer wants a `Uri`, not a `string`. `ChatModelOptions` binds directly from `IConfiguration.Get<ChatModelOptions>()`, where every value arrives as a string; converting to `Uri` here would only move the parsing failure from "provider adapter construction" (where it already surfaces clearly, since that is where the `HttpClient` is built) to "configuration binding" for no added safety. | If `ChatModelOptions` stops being bound directly from configuration. |
| `ASPIRE010` | `bOps.AppHost` | Advisory-only diagnostic about opting into the separate `aspire` CLI's bundled features (a richer local dashboard/run experience). V0.5's AppHost is run with plain `dotnet run` (agentic/06-decisions.md, D-002 — dev/test orchestration only, never a production host) and needs none of that. | If the `aspire` CLI's bundled features become something a contributor actually needs locally. |
| `CA1812` | `bOps.TestFixtures.WindowsService.NoOpWorker` | The analyzer cannot see that `AddHostedService<NoOpWorker>()` instantiates it via DI reflection at runtime, so it reads as an unused internal class. This is a V0.11 test-only fixture (a real, throwaway Windows Service `bOps.Packages.Service.Windows.Tests` installs and deletes per test), not shipped in any product artifact. | Never — the analyzer has no way to see DI-reflection construction; this is a permanent, considered suppression for this fixture. |
